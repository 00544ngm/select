# 员工电脑兼容与故障自诊断设计

## 目标

让安装版在普通非管理员 Windows 账户上稳定完成“提交任务、抓取商品、模型分析、生成报告”，并在外部环境阻断时给出可定位、可恢复的错误，禁止永久停留在“提交中”或只显示 `INTERNAL_ERROR`。

## 已确认问题

1. Electron 子进程使用 `stdio: "ignore"`，API、Worker、前端的真实错误全部丢失。
2. 前端 `apiFetch` 没有超时，IPC 或本地 API 无响应会让提交状态永久 pending。
3. `artifact_dir` 默认是相对路径，安装目录为只读时可能产生员工账户特有的写入失败。
4. DPAPI 密钥只属于加密时的 Windows 用户；换用户、复制数据库或旧数据迁移后无法解密。
5. Worker 对未知异常仅保存通用 `INTERNAL_ERROR`，没有保存安全的失败阶段和异常类别。
6. 当前验收偏重开发机和管理员环境，没有覆盖只读安装目录、新用户和路径特殊字符。

## 设计

### 1. 当前用户专属运行目录

Electron 创建 `%LOCALAPPDATA%\组合选品控制台` 下的 `data`、`runtime`、`logs`、`artifacts`、`temp`。所有子进程接收显式环境变量和 `cwd`，数据库、心跳、产物、日志和临时数据不得写入安装目录。

### 2. 可保留的子进程日志

进程监督器将 API、Worker、前端的 stdout/stderr 分别追加到当前用户日志目录，控制单文件大小并保留有限历史。界面“打开日志”必须打开同一目录。日志不得记录 API Key、桌面会话令牌或完整请求密钥字段。

### 3. 有界请求与提交恢复

前端 API 客户端对桌面 IPC 与本地 Fetch 整体使用 15 秒 deadline；任务执行仍由后台异步进行，不受该超时影响。超时抛出稳定的 `DESKTOP_API_TIMEOUT`，React Query mutation 必须退出 pending，按钮恢复可点击。

### 4. 分阶段安全错误

Worker 保留现有内部堆栈日志，但数据库只保存安全信息：稳定错误码、中文可读消息、失败阶段、异常类型。未知异常示例：`任务在“创建浏览器”阶段失败（PermissionError），请导出诊断日志。` 不回显原始异常文本中的密钥或请求内容。

### 5. 密钥与环境预检

任务提交前的桌面预检检查：运行目录可写、数据库可写、Worker 心跳有效、内置浏览器存在、启用供应商至少有一个已选择且已验证模型、API Key 可由当前 Windows 用户解密。DPAPI 失败返回 `PROVIDER_CREDENTIAL_REENTRY_REQUIRED`，提示员工在本机重新输入密钥。

### 6. 验收边界

软件侧必须通过普通账户等价环境测试：只读安装根目录、中文/空格/`#`/`%` 的用户数据路径、API 挂起、Worker 退出、浏览器缺失、跨用户密钥。外部 CAPTCHA、企业代理或杀毒软件拦截不能被软件绕过，但必须快速失败并生成可用日志，不能假死。

## 非目标

- 不把 API Key 跨 Windows 用户共享。
- 不关闭系统安全软件或绕过网站 CAPTCHA。
- 不改变现有业务分析与评分规则。
