# 结果研究工作台与历史记录设计规格

**日期：** 2026-07-27

**状态：** 已通过交互设计，等待书面规格确认

**范围：** 假设方向结果页、平台关键词核验、交叉验证展示、历史记录页、全局中文排版

## 1. 目标

把现有纵向堆叠的分析结果改造成适合反复研究和横向判断的工作台，同时补足主品图片、方向关键词、平台搜索结果与任务时间信息。改造只增强数据透传和展示，不改变抓取、模型提示词、模型输出、方向评分、综合评分、任务状态或原始分析内容。

成功标准：

- 用户在一个桌面视口内能看到方向列表、当前方向核心指标和主要分析内容，不需要逐条向下展开。
- 主品已有图片时显示真实主品图片；历史数据没有图片时明确显示“历史无图”，不使用替代图。
- 每个方向展示可复制、可搜索的英文关键词，并清楚区分“模型建议”和“平台核验”。
- Walmart 搜索结果展示真实标题、链接、图片和已有商品字段，但不因“搜到商品”自动标为精准。
- 历史记录展示北京时间、任务耗时和“主品 -> 最高分辅品方向”摘要。
- 现有任务结果中的方向、分数、成本、策略、证据与交叉验证原文保持不变。

## 2. 不在本次范围内

- 不修改 LLM 提示词，不重新生成、润色或校正模型结论。
- 不改变方向排序依据、分数计算、综合评分或任务完成条件。
- 不将 Walmart 搜索改成分析任务的必经步骤，也不因搜索失败把已完成任务改成失败。
- 不抓取或伪造 Amazon 商品卡片；没有可靠结构化结果时只提供关键词搜索链接。
- 不为旧任务补造图片、关键词、完成时间或搜索证据。
- 不把搜索结果永久写回模型原始输出；搜索状态是独立的前端核验状态。

## 3. 数据边界与来源

### 3.1 后端结果序列化

在 `backend/application/analysis_runner.py` 的 `_serialize_hypothesis` 中，仅补充当前领域对象已经拥有但尚未传给前端的展示字段：

- 结果级 `product_images: string[]`，直接来自 `result.product.images`。
- 结果级 `product_price: string`、`product_rating: string`、`product_review_count: string`，直接来自对应主品 DTO 字段。
- 结果级 `keyword_pack: string[]`，直接来自 `result.keyword_pack`。
- 每个 `structured_directions` 项增加：
  - `motivation_evidence: string`
  - `deep_arguments: Record<string, unknown>`
  - `delivery_checklist: Record<string, unknown>`
  - `keywords: Record<string, string>`，原样来自方向对象，当前已知键为 `en` 与 `amazon`

方向关键词不调用模型重写。平台查询词按确定顺序选择：优先使用方向已有 `keywords.amazon`，其次使用 `keywords.en`，两者都缺失时才从方向名称中现有括号英文名提取并标准化；仍无法获得查询词时显示“暂无可核验关键词”。结果级 `keyword_pack` 继续在独立标签页原样展示，不自动分配给某个方向。该字段是模型给出的检索入口，不是平台已经验证的“精准关键词”结论。

所有既有字段原样保留；既有 `sections` 继续作为原始结果和兼容展示的数据源。序列化不得重算分数或改变方向顺序。

### 3.2 前端类型

在 `frontend/lib/api/types.ts` 中扩展 `StructuredDirection` 与 `JobResultPayload`，类型与后端新增字段一一对应。新增字段均允许缺失，以保证旧任务和旧结果仍可打开。

### 3.3 平台搜索

Walmart 继续使用现有 `POST /api/v1/search`，请求体为 `{ keyword }`，返回商品 `title`、`url`、`price`、`rating`、`review_count`、`image`。前端新增强类型搜索函数和按方向保存的查询状态。

Amazon 使用：

`https://www.amazon.com/s?k=<URL 编码后的关键词>`

该链接仅表示“在 Amazon 打开搜索”，不表示平台已返回或验证了任何商品。

## 4. 准确性与状态规则

页面必须把三类信息分开标识：

1. **原始数据**：主品标题、链接、图片、价格、评分等抓取字段。
2. **模型分析**：方向、分数、动机、成本、策略、深度论证和交付建议。
3. **平台核验**：用户主动搜索后由平台实时返回的商品结果。

Walmart 请求状态只使用以下文案：

- `待核验`：尚未发起本方向搜索。
- `平台已返回`：接口成功并返回商品；不代表语义精准。
- `无结果`：平台正常响应但没有可展示商品。
- `搜索失败`：网络、反爬、超时或解析异常。

本次不新增自动语义分类器，因此前端不得自动显示“精准匹配”。每个搜索结果卡片同时使用“平台实际返回”和“相似候选（未确认精准）”标签，用户根据标题、图片和链接自行判断。后续若增加精准判定，必须有单独规则、证据和测试，不能复用“结果数量大于零”。

真实示例 `non slip pizza cutting mat` 曾返回披萨面团/烘焙硅胶垫。该结果包含 Pizza 和 Mat，但用途不是披萨切割承托，因此只能算相似结果，证明返回数量不能作为精准判断依据。

## 5. 结果研究工作台

### 5.1 页面结构

采用已批准的“Research Workbench”布局：

- 顶部：面包屑、任务名称、北京时间、任务耗时。
- 主品带：主品图片、标题、来源平台、现有商品指标、模型与综合评分。
- 视图标签：方向研究、商品与证据、关键词包、交叉验证。
- 主工作区左侧：固定方向列表，默认按现有分数降序显示；每项展示排名、名称、类型/动机、证据层级和分数。
- 主工作区右侧：当前选中方向的完整详情；默认选中最高分方向。

桌面端使用稳定的双栏网格，方向列表在可用高度内独立滚动。移动端改为上方横向/紧凑方向选择器与下方详情，不能产生文本遮挡或横向溢出。

### 5.2 当前方向详情

详情区按信息责任分组，不把多个页面区块包进嵌套卡片：

- 方向标题：中文名、英文名、分数、证据层级。
- 指标带：组合类型、购买动机、1688 成本、价格策略、粘性。
- 关键词与平台核验：模型建议词、查询词、核验状态、Walmart 商品结果、Amazon 搜索入口、复制关键词。
- 深度分析：用户理由、卖家理由、紧迫性、差异化、风险控制、场景适配和原始分数。
- 交付清单：组合展示、Listing 卖点、定价动作、上线动作。
- 对应证据：原始动机证据及现有结果中的证据内容。

方向切换只切换展示数据，不重新请求模型。Walmart 搜索必须由明确按钮触发，并提供加载、成功、无结果和失败状态；一个方向的失败不影响其他方向。

### 5.3 图片

- 主品有 `product_images` 时显示第一张并允许查看其余图片；图片加载失败显示中性占位和“图片加载失败”。
- Walmart 结果仅显示接口返回的 `image`；无图时显示“平台未返回图片”。
- 使用固定宽高或纵横比，图片加载不能导致整体布局跳动。
- 所有外部图片必须保留可读的商品标题替代文本。

## 6. 交叉验证展示

`frontend/components/jobs/cross-review-panel.tsx` 只把现有 `raw` 内容按可逆规则排版：保留完整原文，识别已有换行、编号和标题以形成段落；无法识别时使用保留换行的纯文本块。不得调用 LLM、删减句子、改写结论或改变字段顺序。

错误项继续展示原始 `error`，并与正常原文视觉区分。用户始终能查看完整原始内容。

## 7. 历史记录

### 7.1 列表数据

现有 `JobSummary` 只有结果摘要，无法直接展示主品和最高方向。列表接口在不改变持久化结构的前提下，从已保存的 `request_payload` 与 `result_payload` 投影以下可选字段：

- `product_title`
- `product_image`
- `top_direction_name`
- `top_direction_keywords`，原样保存方向关键词对象，不生成新词
- `top_direction_score`
- `top_direction_type`

投影只读取已保存数据；结果不存在、任务未完成或旧数据缺字段时返回 `null`/空数组，不推测内容。

### 7.2 时间规则

- 开始时间使用 `created_at`。
- 完成或失败时间使用 `updated_at`。
- 耗时为二者差值，仅在 `completed` 或 `failed` 状态展示最终耗时；运行中显示“已运行”时长。
- 前端统一转换为 `Asia/Shanghai`（UTC+8）并明确标注“北京时间”。
- 按自然日分组为“今天”“昨天”或完整日期。

### 7.3 列表布局

桌面表格列为：匹配时间、任务与主品、最高分辅品方向、结果、状态、操作。每行显示：

- 开始、结束/更新时间和耗时。
- 任务名称、主品标题和真实图片；旧任务无图显示“历史无图”。
- `主品 -> 最高分辅品方向`，包含方向名和查询关键词。
- 最高方向分、综合分和方向类型。
- 已完成、失败、运行中或排队中状态。
- 查看、下载或重试等现有可用操作。

移动端每条记录转为紧凑纵向行组，但仍按时间、主品、方向、结果、状态的顺序阅读。

## 8. 视觉与排版

沿用现有墨绿导航和绿色语义主色，增加灰绿画布、白色内容面和蓝/橙/红状态色，避免全屏纯白。卡片圆角不超过 6px，页面区块以无嵌套的面板和分隔线组织。

- 中文界面字体栈：`Microsoft YaHei UI`, `Noto Sans SC`, sans-serif。
- 正文不低于 14px，关键数据不低于 13px。
- 分析正文行高 1.65 至 1.75。
- 英文关键词使用等宽字体，但字号不得小于 13px。
- 字间距固定为 0，不随视口缩放字体。
- 方向列表、图片、分数和操作按钮使用稳定尺寸，切换状态不得引发布局跳动。
- 所有仅图标按钮使用 Lucide 图标、可访问名称和悬停提示。

## 9. 错误与兼容处理

- 旧结果没有新增字段：继续展示现有 `sections`，缺失区域显示明确空状态，不抛异常。
- 主品图片 URL 失效：保留标题和链接，显示加载失败占位。
- 方向无英文关键词：禁用平台核验按钮并解释“暂无可核验关键词”。
- Walmart 返回空数组：显示“无结果”，保留关键词和再次搜索入口。
- Walmart 返回 502 或网络错误：显示“搜索失败”及可读错误，不改变任务状态。
- 原始交叉验证内容无法结构化：按纯文本保留换行展示，绝不丢失原文。
- 时间字段无效：显示“时间不可用”，不得展示错误耗时。

## 10. 测试与验收

### 后端

- 序列化测试验证主品图片、关键词和方向详细字段均来自原对象且顺序、分数未变。
- 旧/空字段测试验证新增字段为空时仍能成功返回。
- 任务列表 API 测试验证完成、失败、运行中和旧任务的摘要投影。
- 搜索路由测试验证请求校验、成功映射、无结果和失败响应。

### 前端

- 类型与数据辅助函数测试：英文名提取、北京时间、耗时、旧数据空状态。
- 组件测试：默认选中最高分方向、方向切换、关键词复制、搜索四种状态、主品/商品图片回退。
- 交叉验证测试：格式化前后原始文本内容完整一致。
- 历史列表测试：匹配时间、主品到方向摘要、历史无图、失败任务和分页。
- 可访问性测试：标签页、方向选择、按钮名称、键盘操作和图片替代文本。
