# 全品类食品准入门槛与模型复核设计

## 背景

软件面向除食品以外的全品类商品，主品和辅品都不能是食品。当前实现依赖少量确定性非食品词组；当标题没有命中白名单时，即使商品明显是金属锅铲等非食品，也会返回 UNKNOWN 并直接让任务失败。

## 目标

- 明确食品必须阻断。
- 明确非食品直接放行。
- 规则无法判断时使用当前任务所选模型进行二次复核。
- 模型不可用或仍不确定时允许任务继续，但保存并显示人工复核提醒。
- 主品和每个辅品使用同一套食品准入规则。
- 方案适配全品类，不能依靠为单个商品不断追加特例。

## 非目标

- 不支持任何人类食品、饮料、药品、营养补充剂、宠物食品或宠物零食作为主品或辅品。
- 不自动改写历史失败任务；修复后由用户重新提交生成新任务。
- 不引入独立的新 API 配置，复用当前任务选择的供应商和模型。

## 方案选择

采用“规则优先 + 模型复核”。

纯词表方案运行便宜但无法覆盖全品类；全量模型分类覆盖广但增加每个商品的延迟和费用。分层方案让高置信度规则直接决策，只对不确定商品调用模型，在覆盖面、稳定性和成本之间最平衡。

## 状态模型

分类结果统一为四种状态：

- `confirmed_non_food`：规则或模型确认非食品，正常分析。
- `confirmed_food`：确认食品，执行阻断。
- `likely_non_food`：模型倾向非食品但证据有限，继续分析并显示提醒。
- `needs_review`：规则和模型都无法确认，继续分析并标记人工复核。

每次判定必须保存：对象角色、状态、来源、置信度、食品证据、非食品证据、中文理由和处理动作。没有明确证据的结果不得升级为 `confirmed_food`。

## 数据流

1. 抓取商品标题、类目、属性、描述和要点。
2. 确定性规则识别高置信度食品和非食品证据。
3. 规则结论明确时直接返回。
4. 规则冲突或证据不足时，调用当前任务选择的模型进行结构化复核。
5. 校验模型 JSON 架构、状态、置信度、理由和证据；解析失败按既有重试策略重试。
6. 重试失败或模型仍不确定时降级为 `needs_review`，任务继续执行。
7. 将分类证据写入任务结果，供结果可靠性和员工操作提示使用。

## 准入与方向处理

- 主品为 `confirmed_food`：整个任务停止，说明食品证据。
- 主品为其他三种状态：任务继续；后两种状态展示复核提醒。
- 辅品为 `confirmed_food`：只淘汰对应组合方向，不影响其他方向。
- 辅品为其他三种状态：方向继续；后两种状态降低证据等级并提示复核。
- 分类模型调用失败本身不能造成整个任务失败。

## 规则层边界

规则层从“枚举所有非食品名称”调整为“高置信度证据识别”：

- 食品强信号包括明确可摄入的产品类型、类目和用途；必须区分容器、工具、设备等非食物实体。
- 非食品强信号优先使用平台类目、产品类型和实体用途，再参考标题短语。
- `food container`、`pet bowl`、`water bottle` 等包含食品词但实体不可摄入的商品应作为非食品强信号。
- 冲突证据不得由单一关键词强行覆盖，必须进入模型复核。

## 模型复核契约

模型输入仅包含抓取后的商品事实，不包含预设结论。输出必须为严格结构化对象：状态、置信度、实体类型、是否设计为摄入、理由、引用证据。

只有“设计为供人或动物摄入”且具有商品事实证据时才能返回 `confirmed_food`。食品接触用品、烹饪器具、包装容器、喂食器具、食品加工设备均属于非食品实体。

## 页面呈现

员工看到中文、可解释的结论，而不是笼统英文错误：

- 商品类型结论。
- 判断依据及来源。
- 系统处理结果。
- 是否需要人工复核。

确认非食品示例：标题和类目表明该商品是不锈钢厨房锅铲，不是供人或宠物摄入的商品，因此允许继续分析。

确认食品示例：商品属于宠物零食，证据来自类目和标题，因此不符合准入范围并停止该任务或方向。

## 容错与可观测性

- 记录规则决策、是否触发模型复核、模型解析结果和降级原因。
- 对外错误和结果不暴露模型原始内部响应或凭据。
- 分类失败与业务食品阻断使用不同错误码和状态，避免员工把服务故障理解为商品不能做。

## 测试与验收

- 金属锅铲、家具、服装、工具、宠物用品等非食品正常放行。
- 水杯、饭盒、储物罐、宠物碗等包含食品相关词但不可摄入的商品正常放行。
- 人类食品、饮料、药品、营养补充剂、宠物食品和宠物零食明确阻断。
- 中英文标题、类目冲突和混合证据进入模型复核。
- 主品食品阻断整个任务；辅品食品仅淘汰对应方向。
- 模型返回无效 JSON、超时或不确定时任务继续并展示复核提醒。
- 金属锅铲历史失败标题作为固定回归样例，不能再触发 `PRODUCT_TYPE_VERIFICATION_REQUIRED` 任务失败。

## 安全与隐私

模型复核复用已配置客户端，不复制或记录 API Key。日志和结果只保存商品事实、分类结论与非敏感证据。
