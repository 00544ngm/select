# 模型目录历史排序、搜索与自动验证设计

## 目标

模型验证成功记录不再因固定 24 小时窗口消失。API 设置页能够自动验证已选模型和最近使用模型，并提供搜索、历史验证排序、使用记录排序及“最近使用模型”快捷入口，使位于长目录末尾的模型（例如 5.6 系列）无需翻阅多页即可找到。

## 范围与边界

- 支持 OpenAI、DeepSeek 与自定义 API 的现有模型目录。
- 自动验证范围固定为：当前勾选使用的模型，以及最近使用的 10 个模型。
- 不自动验证全部目录模型，避免大量请求、限流和不必要的 API 消耗。
- 不自动切换到其他付费模型，不对失败验证无限重试。
- 保留现有任务、供应商配置、DPAPI 加密 API Key 和历史模型验证数据。

## 数据模型

在 `provider_model_validations` 增加：

- `last_used_at`：模型最近一次被成功提交到任务的时间，可为空。
- `use_count`：成功提交任务的累计次数，默认 0。
- `last_auto_tested_at`：最近一次后台自动验证时间，可为空。
- `connection_revision`：该次验证对应的供应商连接修订号，默认 1。

在 `provider_configurations` 增加 `validation_revision`，默认 1。API Key、服务地址或协议改变时仅递增该值，不删除历史模型验证记录。模型验证结果的 `connection_revision` 与供应商当前 `validation_revision` 相同，才可作为当前连接的有效验证。

新增 0009 数据库迁移。迁移只增加可空字段和带默认值的计数字段，不删除或重写既有验证记录。

“最近使用”以任务成功进入队列为记录边界，而不是等报告完成。这样能够真实反映员工选择过的模型，同时失败报告不会丢失本次选择历史。

## 验证有效性

- 移除固定 24 小时验证 TTL。历史成功验证持续有效。
- 以下连接身份改变时，既有验证不得继续作为当前连接的有效证明：API Key、服务地址、接口协议。
- 保存上述连接变化后递增连接修订号并触发重新发现/验证流程；历史记录仍保留为展示信息，但修订号不一致时不能直接用于任务准入。
- 上游明确返回模型不存在、无权限或不可用时，将该模型最新状态更新为不可用。
- 临时网络错误只记录最新失败，不删除更早的成功时间和使用历史。

## 自动验证流程

打开 API 设置并加载供应商后：

1. 后端返回模型目录、历史验证、选择状态和使用统计。
2. 前端计算“已选模型 + 最近使用 10 个模型”的去重集合。
3. 当前页面会话对每个模型最多发起一次自动验证。
4. 验证逐个隔离执行，单个失败不阻断其他模型，也不锁住搜索、筛选和离开页面。
5. 每个结果完成后局部刷新目录状态。

任务提交时：

- 从未验证的已选模型先执行一次轻量验证，成功后继续入队。
- 有历史成功记录的模型不因时间超过 24 小时而被拒绝。
- 上游明确不可用时停止提交，返回包含供应商、模型和原因的可操作错误。
- 提交成功后更新 `last_used_at` 和 `use_count`。

## 模型目录界面

目录工具栏包含：

- 模型搜索框：按模型名称包含匹配，不区分大小写。
- “全部模型”筛选。
- “最近使用模型”筛选：最多显示最近 10 个。
- “已验证模型”筛选。
- 排序：智能排序、最近使用、使用次数、最近验证、模型名称。

智能排序优先级：

1. 已勾选使用。
2. 最近使用。
3. 最近验证成功。
4. 其他目录模型。

同一优先级内先按时间倒序，再按模型名称稳定排序。搜索结果不分页；普通筛选保持每页 10 个。验证成功或使用后模型进入智能排序第一页，但当前搜索文本不被清空。

模型卡展示：

- 使用状态。
- 历史验证结果和时间。
- 最新自动验证结果。
- 最近使用时间。
- 累计使用次数。

## API 与组件边界

- Repository 负责验证记录、选择状态及使用统计持久化。
- ProviderService 负责验证有效性、自动验证候选集合和单模型验证。
- JobService/任务 API 负责提交前验证与提交成功后的使用记录。
- Provider API schema 返回新增时间和计数字段，不在前端推导数据库状态。
- 前端将搜索、筛选、排序实现为纯函数，便于独立测试；请求调度与卡片渲染分离。

## 异常与并发

- 自动验证使用短超时和单次调用。
- 同一页面会话同一供应商/协议/模型只自动验证一次。
- 验证按钮和自动验证共享模型级 pending 状态，避免同一模型并发重复调用。
- 一个模型失败不影响目录其他模型。
- 页面卸载后不继续更新已卸载组件；已发送请求由后端正常收尾。
- 连接配置改变时清空当前自动验证会话指纹，保存完成后按新连接重新执行。

## 测试与验收

- 数据迁移保留现有记录并正确初始化新增字段。
- 超过 24 小时的成功验证仍可选择和提交。
- API Key、地址或协议改变后要求新连接重新验证。
- 打开设置页只自动验证已选及最近 10 个模型，去重且每会话一次。
- 搜索 `5.6` 直接返回匹配模型且不分页。
- 最近使用、使用次数、最近验证和智能排序稳定正确。
- “最近使用模型”最多显示 10 个。
- 任务成功入队更新最近使用时间与次数。
- 自动验证失败不会造成整页转圈或清除历史成功记录。
- 后端、前端、桌面全量回归、生产构建、数据库迁移和整包员工路径冒烟通过后再发布新版安装包。

## 回滚

前端可回退为原模型目录分页，不影响新增字段。后端读取新增字段时均允许空值；若回退应用版本，0009 新增列保留但不会影响旧代码。禁止通过删除迁移或清空验证表回滚。
