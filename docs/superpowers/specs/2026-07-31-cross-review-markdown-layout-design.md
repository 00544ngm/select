# 交叉验证 Markdown 文档式排版设计

日期：2026-07-31

## 背景

交叉验证结果当前按逐行 `span + whitespace-pre-wrap` 显示。模型返回的 Markdown 标题、加粗、列表和表格符号被当作普通字符，因此内容虽然完整，但层级不清晰、扫读困难。

## 目标

- 采用已确认的 A 方案：文档式 Markdown。
- 不改写模型内容，不重新生成或覆盖历史任务。
- 把标题、段落、列表、强调和表格渲染为清晰的报告结构。
- 默认显示排版结果，并提供可折叠的模型原文用于审计。
- 不执行模型返回的 HTML、脚本或其他不可信页面内容。

## 非目标

- 不把模型内容重组为业务卡片。
- 不引入目录导航或改变交叉验证数据结构。
- 不修改交叉验证提示词、评分逻辑、API 或数据库。
- 不对模型文本进行翻译、摘要或措辞修正。

## 方案

### 解析层

扩展 `frontend/lib/cross-review-format.ts`，把原始文本解析为受控文档节点。支持：

- ATX 标题：`#` 到 `######`
- 有序列表：`1.`、`1)`、`1、`
- 无序列表：`-`、`*`、`+`、`•` 等
- 段落与空行分组
- 行内强调：`**粗体**`
- Markdown 管道表格，包括表头分隔行

解析器只识别上述白名单语法。HTML 标签始终作为普通文本，由 React 自动转义；不使用 `dangerouslySetInnerHTML`。

### 展示层

`CrossReviewPanel` 使用独立的文档渲染组件：

- 一级至三级标题形成明显但克制的字号和边界层级。
- 列表使用真实 `ul/ol/li` 语义。
- 表格放入横向滚动容器，在窄屏不撑破页面。
- 段落保持舒适行高和合理间距。
- 关键词粗体使用 `strong`，不改变原文顺序。
- 底部提供“查看模型原文”折叠区，以 `pre-wrap` 显示完整原始文本。

视觉延续当前绿色、克制、信息密集的工作台风格，不引入新的全局字体、主题或装饰动画。

### 数据完整性

解析结果仅用于显示。原始字符串继续作为唯一审计来源，并满足：

- 原始字符串不被写回或改动。
- 原文折叠区的 `textContent` 与 API 返回值完全一致。
- 不支持的 Markdown 语法按普通文本展示。
- 空文本不渲染文档节点。

## 测试

### 解析单元测试

- 标题层级识别。
- 有序与无序列表分组。
- 粗体片段识别且字符顺序不变。
- 管道表格识别和单元格保留。
- Windows 换行、空格和结尾换行可通过原始字符串审计。
- HTML 输入不产生可执行 DOM。

### 组件测试

- 交叉验证标题显示为 heading 语义。
- 列表显示为 `list/listitem`。
- 表格显示为 `table`。
- 模型原文默认折叠，展开后字符完全一致。
- 旧的无结构纯文本仍可阅读。

### 回归

- 前端交叉验证相关定向测试。
- 前端全量测试。
- TypeScript 检查。
- Next.js 生产构建；构建前先停止 Next dev，构建后重启并探活。

## 失败与回退

- 某段无法识别时按普通段落显示，不丢弃内容。
- 表格结构不完整时按普通文本显示。
- 如需回退，只恢复旧 `ReviewText` 行级渲染；数据和历史任务无需迁移。
