# 已验证模型置顶与工作台空状态修复设计

## 目标

让用户能区分“正在提交”和“当前没有可用模型”，并让真实验证成功的模型自动出现在模型目录第一页最前方，无需翻页寻找。

## 已确认行为

1. 工作台无可用主模型时，提交按钮保持禁用并显示“请先配置 API”，不得显示旋转的“提交中”。
2. 连接测试只负责发现模型；模型必须再通过真实任务路径验证，才允许进入工作台。
3. 模型目录按以下优先级稳定排序：
   - 24 小时内真实验证成功；
   - 当前默认模型；
   - 其余模型保持供应商目录原始顺序。
4. 任一模型验证成功后，模型目录自动回到第一页；该模型因排序规则显示在第一页前部。
5. 验证失败或临时错误的模型不置顶，保留在原目录顺序中。
6. 已验证卡片继续显示“已验证（24 小时内）”和最近测试时间。

## 实现边界

- 仅修改前端展示、分页状态和相关测试。
- 不改变后端模型验证、24 小时门禁、数据库结构、API Key、任务评分或历史结果。
- 已安装桌面版必须重新构建并覆盖安装，才能使用新界面。

## 验证

- 用前端组件测试覆盖无模型空状态、已验证置顶、验证成功跳回第一页。
- 执行前端定向测试、类型检查与生产构建。
- 重新生成 Windows 安装包，并核对安装包哈希。
