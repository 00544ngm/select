# 模型勾选与桌面密钥链路修复设计

## 目标

让用户在 API 设置中验证模型后直接勾选一个或多个可用模型，并让工作台只展示这些已勾选且仍在 24 小时验证有效期内的模型。同时修复桌面 API 与 Worker 使用不同密钥解密机制导致的任务失败。

## 已确认交互

- 移除“默认模型”输入或下拉框，不再要求用户维护唯一默认值。
- 模型验证成功后显示“使用此模型”复选框；未验证、验证失败或验证过期的模型不可勾选。
- 同一供应商允许勾选多个模型，选择状态持久化。
- 工作台仅列出已启用、已勾选且 24 小时内验证成功的模型；任务提交时仍只选择一个模型，不会自动并发调用多个模型。
- 模型重新验证失败或验证过期时不进入工作台，即使历史选择状态仍存在。

## 数据与 API

在 `provider_model_validations` 增加 `is_selected` 布尔字段，默认 false。模型目录 DTO 增加同名字段。新增本地设置接口用于切换单个模型的选择状态；服务端只允许选择当前协议下、24 小时内验证成功的模型，取消选择始终允许。

保留数据库中的 `default_model` 作为旧数据和旧任务兼容字段，但不再由界面展示或作为工作台准入依据。连接测试仍需要一个探测模型时，使用当前草稿模型或供应商内置回退值；模型是否可执行以逐模型验证为准。

## 桌面密钥链路

新增单一 `create_provider_crypto(settings)` 工厂：桌面模式返回 Windows DPAPI，服务端模式返回现有 Fernet `ProviderCrypto`。API 依赖、Worker 解析器和应用启动时的旧配置迁移统一调用该工厂，禁止各自构造不同实现。

## 错误处理

- Worker 解密失败继续返回可读的“API Key 必须重新录入”，但正常桌面配置不应再触发。
- 选择未验证或过期模型返回不可重试的配置错误。
- 上游模型调用失败保留供应商原始错误分类，不把模型不可用误报为密钥丢失。

## 验证

- 后端回归测试证明桌面 API 与 Worker 获得同一种 DPAPI 实现。
- 后端测试覆盖多选、取消、未验证禁止选择、选择状态公开输出和工作台准入。
- 前端测试覆盖复选框、移除默认模型、工作台仅显示已勾选模型。
- 使用现有加密保存的 OpenAI 与 Maike 配置执行真实连接/模型验证和至少一个任务路径测试；不输出或落盘明文密钥。
- 前后端全量测试、类型检查、生产构建、桌面整包启动与安装包哈希验证。
