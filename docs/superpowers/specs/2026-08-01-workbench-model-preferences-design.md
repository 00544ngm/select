# 工作台分入口模型偏好与任务名称布局设计

## 背景

工作台的任务名称、供应商和模型目前都放在“高级选项”中。用户经常切换模型，但页面不会稳定记住每个任务入口的长期选择；任务名称也离商品链接较远，容易被忽略。

## 已确认目标

- 假设分析、对比审判、批量任务分别记住自己的供应商和模型选择，互不影响。
- 下拉框的临时切换只影响当前任务；只有点击“保存为默认选择”才改变该入口后续任务的默认值。
- 任务名称移动到链接输入区域附近，点击启动时随任务请求一起保存，不需要单独的名称保存按钮。
- 不保存 API Key，不改写历史任务，不新增用户账户体系。

## 交互设计

### 单链接入口

假设分析和对比审判的主要输入区按以下顺序排列：

1. 任务名称（可选）。
2. 商品链接。
3. 分析或启动按钮。

“高级选项”改名为“模型设置”，只包含供应商、模型、当前默认状态和“保存为此入口默认选择”按钮。

### 批量任务入口

任务名称继续与批量链接输入放在主要输入区；模型设置区域提供同样的保存按钮。批量任务拥有独立偏好键，不与两个单链接入口共享。

### 保存语义

- 用户改变供应商或模型后，当前任务立即使用所选值，但长期默认不变。
- 点击保存按钮后，仅保存当前入口的 `{provider, model}`。
- 保存成功后显示明确反馈，并标记当前选择为“已保存默认”。
- 再次改变下拉框时显示“尚未保存”，直到再次点击保存。

## 数据与恢复规则

浏览器本地仅保存三个版本化键：

- `hypothesis`
- `judgment`
- `batch`

每条记录只包含供应商 slug、模型名和版本号，不包含任务名称、链接或任何凭据。

供应商目录加载完成后按完整 `provider:model` 身份验证偏好：

- 偏好仍可用：恢复该选择。
- 供应商停用、测试失败或模型被移除：不使用旧偏好，回退到当前第一个可用供应商及其默认/可用模型，并提示原默认已失效。
- 没有可用供应商：沿用现有“前往 API 设置”阻断逻辑，保存按钮禁用。
- 本地数据损坏或版本不支持：忽略并安全回退，不阻断任务表单。

## 组件边界

- 新增小型偏好存储模块，负责解析、校验、读取和写入，不直接操作表单 UI。
- `ModelSelect` 接收入口标识并负责恢复选择、显示保存状态和触发显式保存。
- 三个任务表单继续负责构造任务请求；任务名称随现有提交请求入库。
- 供应商可用性继续复用现有 `usePrimaryProviders` 规则，不另建宽松目录。

## 测试要求

- 先写失败测试，再实现生产代码。
- 验证三个入口的偏好互不影响。
- 验证临时切换不会持久化，点击保存后重新挂载可恢复。
- 验证任务名称位于链接附近，并随提交请求保存。
- 验证失效、损坏和旧版本偏好安全回退且有提示。
- 验证没有可用供应商时不能保存偏好或提交任务。
- 运行相关组件测试、前端全套测试、类型检查和生产构建。

## 明确不做

- 不跨设备同步偏好。
- 不自动保存每次下拉切换。
- 不持久化任务名称或商品链接。
- 不修改 API Key、供应商连接测试、后端路由或历史任务数据。
