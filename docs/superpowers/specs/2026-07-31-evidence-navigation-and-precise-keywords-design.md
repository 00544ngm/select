# 补证导航与精准关键词交互设计

## 目标

让员工看到“补充证据后复核”时能够直接到达需要核对的证据，同时把混合显示的 Amazon 与英文关键词拆成可理解、可复制、可执行的检索入口。

本功能适用于所有非食用品类，不针对水平尺、家具垫或任何单个商品写特例。

## 员工行动按钮

只有待复核方向的“补充证据后复核”显示为按钮。`pass`、完整硬拒绝和历史证据不完整等其他结论保持非交互标签，避免制造无意义跳转。

点击按钮后的固定行为：

1. 展开当前方向的“深度分析”。
2. 平滑滚动到当前方向的“待验证证据”区域。
3. 把键盘焦点移动到该区域，并显示短暂高亮。
4. 若历史任务没有具体 `missing_evidence`，则定位到“为什么 / 下一步 / 这意味着”行动说明区。

每个方向使用自身稳定的 DOM 标识和引用，不跨方向跳转。切换方向后，按钮始终只控制当前详情。

## 关键词手风琴

原来的单行混合文本替换为两个独立手风琴。

### Amazon 精准关键词

- 默认展开。
- 每个方向只显示一条建议精准检索短语。
- 提供“复制精准词”和“打开 Amazon 搜索”。
- 搜索链接只把该短语作为查询参数，不携带历史 Amazon 页面跟踪参数。
- 显示边界说明：这是模型建议的精准检索入口，不代表 Amazon 已验证销量、相关性或具体商品可用性。

### 英文通用关键词

- 默认收起。
- 显示一个跨平台英文扩展短语。
- 提供独立的“复制通用词”。
- 不与 Amazon 精准词拼接，不再显示 `amazon:`、`en:` 前缀长句。

当字段为空时，对应手风琴显示“暂无可用关键词”，复制及搜索按钮禁用。

## 新任务关键词数据规则

保留现有 `keywords.amazon` 与 `keywords.en` 数据结构，避免不必要的数据库迁移和 API 破坏。

- `keywords.amazon`：恰好一条 Amazon 精准检索短语。
- `keywords.en`：恰好一条英文通用扩展短语。

Amazon 精准词生成约束：

- 必须包含候选辅品的核心品类名。
- 只有在区分商品所必需时才加入规格、用途或适配对象。
- 禁止加入 `amazon`、促销词、无事实依据的品牌、完整营销标题和重复近义词。
- 不使用主品品牌冒充辅品品牌。
- 不声称经过平台搜索或销量验证。

英文通用词用于跨平台扩展，可以比 Amazon 精准词更偏用途，但仍必须描述同一候选辅品。

## 历史兼容

不重算、不覆盖历史任务。

- 历史 `keywords` 已是对象时，直接分别读取 `amazon` 与 `en`。
- 历史值是混合字符串时，仅按受控的 `amazon:` 与 `en:` 分隔符拆分；无法可靠拆分的内容放入英文通用关键词，Amazon 精准关键词显示为空。
- 前端不得通过截词或猜测生成“精准词”，以免把宽泛词错误包装为精准词。

## 组件边界

- 新增无副作用的关键词标准化函数，负责兼容对象、混合字符串和空值。
- 新增关键词手风琴组件，负责展开、复制和 Amazon 搜索，不参与业务评分。
- 粘性评分卡负责暴露补证目标引用、展开状态和按钮点击协调。
- 行动指引函数继续只生成语义，不直接操作 DOM。

这些边界保证关键词解析、界面交互和业务决策可以分别测试。

## 可访问性与错误处理

- 行动按钮具有明确名称：“查看待补证据”。
- 手风琴使用原生 `details/summary` 或等价的可访问展开控件。
- 目标区域设置可编程焦点；动画不影响键盘操作。
- 剪贴板写入失败时按钮恢复为“复制失败，请手动复制”，不吞掉错误。
- 浏览器阻止打开新窗口时，Amazon 搜索仍保留为普通链接，可由员工手动打开。

## 验收标准

- 点击待复核结论会展开深度分析并定位、聚焦、高亮当前方向的待验证证据。
- 无具体证据的历史方向会定位到行动说明而不是空白区域。
- Amazon 精准词与英文通用词分开显示、分开复制。
- Amazon 搜索只使用精准词，并正确进行 URL 编码。
- 新任务模型输出满足一条精准词和一条通用词的约束。
- 历史对象与混合字符串均能安全展示，历史数据不被改写。
- 页面不再出现混合的 `amazon: ...; en: ...` 用户可见长句。
- 前端组件、关键词纯函数、提示词契约和全品类回归测试全部通过。

## 非目标

- 本轮不调用 Amazon 广告或关键词销量 API。
- 不把模型建议词描述为经过平台验证的“官方精准词”。
- 不新增员工在线编辑或保存证据的表单。
- 不修改评分、准入门禁、食品拦截或历史任务数据。
