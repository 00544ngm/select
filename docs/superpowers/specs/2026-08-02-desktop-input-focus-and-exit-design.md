# 桌面版输入焦点与彻底退出修复设计

## 问题与证据

用户安装桌面版后反馈中文输入不稳定。新视频显示：连续输入英文字符时文字本身没有丢失，但 Windows 中文输入法候选栏在输入过程中反复出现和重建，符合输入法组合态被焦点变化打断的表现。现有桌面端在点击关闭按钮后并不退出，而是隐藏到一个空白托盘图标；Electron、前端、API 和 Worker 会继续驻留后台。虽然尚不能仅凭视频证明后台进程必然抢焦点，但这种不可见驻留既不符合用户预期，也扩大了干扰输入和资源占用的风险。

## 已确认方案

采用“关闭即彻底退出”的方案：

- 点击主窗口关闭按钮时允许窗口关闭，并触发应用退出。
- 删除托盘创建、空白托盘图标、隐藏到托盘和托盘双击恢复窗口逻辑。
- 保留最小化行为；最小化不得退出或主动重新聚焦窗口。
- 首次启动成功后显示窗口；只有用户明确再次启动同一程序时，单实例事件才允许恢复并聚焦已有窗口。
- 退出时停止 API、Worker 和前端子进程，不能留下桌面版后台服务。
- 不修改商品分析、供应商、数据库内容和历史任务结果。

## 生命周期与错误处理

窗口普通关闭返回 `allow-close`。最后一个窗口关闭后调用 `app.quit()`；`before-quit` 负责设置退出状态并停止受管子进程。退出处理保持幂等，避免关闭事件和退出事件相互递归。若服务启动失败，继续使用现有失败路径停止已启动的子进程并抛出原始错误。

## 测试与发布门禁

遵循 TDD：先把现有“普通关闭隐藏到托盘”断言改为“普通关闭允许退出”，确认测试因旧行为失败，再实现最小修改。随后执行：

1. Electron 生命周期单元测试和 TypeScript 类型检查。
2. 桌面端完整测试，确认渲染进程安全配置不变。
3. 构建 0.1.1 安装包和 `win-unpacked` 版本。
4. 启动整包，验证 UI、API、Worker、心跳和数据库正常。
5. 关闭主窗口后检查 Electron、API、Worker 和前端子进程全部退出。
6. 软件运行期间以及退出后，分别在真实文本框中连续输入英文和中文，确认焦点不被桌面版周期性抢占。

## 边界

本修复不修改 Windows 输入法、不安装键盘驱动、不注册全局快捷键，也不更改其他软件。视频只能支持“输入法组合态疑似被打断”的判断，不能证明所有输入异常都由本软件造成；因此发布结论必须区分自动化生命周期验证与人工中文输入验证。
