# 桌面版浏览器自动恢复与环境排查设计

## 背景

员工电脑覆盖安装 0.1.2 后，假设分析任务可能在 `run_hypothesis` 阶段以 `TargetClosedError` 失败。该异常表示 Playwright 页面、浏览器上下文或整包 Chromium 进程被提前关闭。现有 Walmart 抓取器在 `finally` 中直接关闭页面，清理操作可能再次抛错并覆盖首发异常，导致界面只能看到浏览器已关闭，无法看到最初原因。

## 目标

- 商品抓取阶段发生一次临时浏览器关闭时自动恢复，不要求员工手工排查。
- 自动恢复只发生在模型调用前，不产生重复模型 Token 消耗。
- 模型调用完成后的市场证据浏览器异常不得触发整项模型重跑；保留分析结果并把证据状态降级为待验证。
- 在软件内提供环境检查、日志目录和 Windows 安全中心入口。
- 不关闭安全软件、不修改 Defender 配置、不自动添加排除项。
- 持续失败时给出中文、可执行、可收集证据的错误，不永久重试。

## 方案选择

采用“自动恢复 + 内置排查中心”。只提示无法处理普通临时崩溃，只重启无法解释安全软件或环境问题；组合方案同时覆盖可自动恢复与必须人工处理的边界。

## 架构与职责

### 1. 浏览器管理器

`PlaywrightBrowserManager` 增加明确的健康状态和重启能力：

- 判断 browser/context 是否仍连接。
- 关闭旧资源时逐项容错，任何清理异常不得覆盖业务首发异常。
- 桌面模式下重启时停止旧 Playwright 和 Chromium，再创建全新的 Playwright、Browser、BrowserContext。
- 重启次数由调用方控制，管理器本身不进行无限重试。

### 2. 商品抓取边界

商品抓取只对可识别的浏览器关闭异常执行一次恢复：

1. 第一次抓取出现 `TargetClosedError` 或等价的浏览器断开错误。
2. 安全关闭当前页面；关闭失败仅写日志。
3. 重启浏览器管理器。
4. 用全新页面重新抓取一次。
5. 第二次仍失败时停止，不再重试，并抛出稳定的 `BrowserError`/`ScrapeError`。

重试范围仅包含商品抓取，位于 `ProductTypeReviewer` 和模型生成之前，因此不会重复调用模型。

### 3. 模型调用后的证据降级

`MarketEvidenceService` 在浏览器关闭时：

- 不重新调用主模型或辅助模型。
- 记录证据验证失败原因和异常类型。
- 把市场证据状态保存为“待验证”或“部分验证”。
- 继续序列化并保存已生成的分析结果。

非浏览器类的既有业务错误维持原有处理，不借此吞掉真实模型、数据或契约错误。

### 4. 桌面环境检查

新增后端桌面诊断接口，返回结构化检查项：

- 整包 Chromium 主程序是否存在。
- Chromium 能否启动、创建空白页并正常关闭。
- 数据库、日志、报告和临时目录是否可写。
- Worker 心跳是否新鲜。
- API 与前端服务是否就绪。
- Chromium 是否启动后立即退出；若系统不允许读取安全中心历史，则明确标记“需要人工查看”，不伪造已检查结果。

诊断不得返回 API Key、环境变量密钥、完整请求正文或其他敏感信息。

### 5. 前端错误与操作入口

浏览器类错误显示专用中文说明，并提供：

- “自动修复后重试”：重新提交任务；后台商品抓取负责单次恢复。
- “运行环境检查”：展示每项通过、失败或需人工确认。
- “打开日志目录”：调用现有 Electron IPC。
- “打开 Windows 安全中心”：由 Electron 打开 Windows Security 的病毒防护页面；不修改任何系统设置。
- “返回工作台”：保留现有行为。

Web 开发模式没有 Electron 桥接时，相关按钮显示说明而不调用不存在的 IPC。

## 错误分类

- 首次关闭后恢复成功：任务继续，日志记录一次恢复事件，不向员工显示失败。
- 两次浏览器关闭：`BROWSER_TARGET_CLOSED`，提示运行环境检查。
- 浏览器可执行文件缺失：`DESKTOP_BROWSER_MISSING`。
- 浏览器启动即退出：`DESKTOP_BROWSER_START_FAILED`，提示检查安全中心和日志。
- 目录不可写：`DESKTOP_PATH_NOT_WRITABLE`，显示具体目录类别，不泄露无关用户数据。
- 模型调用后证据浏览器失败：任务成功，证据状态降级，不再次扣费。

## 测试策略

按测试驱动开发执行：

- 浏览器管理器：关闭已断开的资源不抛出，重启创建新实例。
- Walmart 抓取：第一次 `TargetClosedError`、第二次成功；持续关闭时只尝试两次。
- Token 边界：抓取恢复发生在模型调用前；市场证据关闭不重复调用模型。
- 环境诊断：组件存在/缺失、目录可写/不可写、浏览器启动成功/立即退出。
- 前端：浏览器错误显示四个操作入口；Web 模式安全降级。
- 整包：在中文、空格、`#`、`%` LocalAppData 下启动，运行诊断并完成真实商品任务或等价端到端链路。

## 安全与发布

- 不请求管理员权限来关闭或绕过安全软件。
- 不自动写入 Defender 排除项。
- 不记录或打包用户 API Key。
- 新版本覆盖安装保留当前 Windows 用户的数据库和配置；不同 Windows 用户仍需分别录入 API Key。
- 自动化测试、员工等价环境验收和整包冒烟全部通过后，才生成并交付新版安装包及 SHA-256。

## 回滚

浏览器恢复、诊断接口和前端入口均可独立回退。设计不要求新增数据库迁移；历史任务和既有配置无需变更。
