# 交叉评审模型身份与结构化总结设计

## 目标

让员工无需理解 `reviewer_a`、`reviewer_b` 等内部字段，也能立即看懂“哪个模型正在评审哪个模型”；同时把新生成的交叉评审从长篇自由文本约束为清晰、可比较、可执行的结构化报告。

## 展示设计

每个折叠项标题使用真实模型身份：

- `DeepSeek（deepseek-v4-pro）评审 Claude（claude-opus-5）`
- `Claude（claude-opus-5）评审 DeepSeek（deepseek-v4-pro）`

模型身份优先读取交叉评审状态中持久化的 `reviewers` 数组，并按结果键的方向解析评审方和被评审方。身份由服务名称、协议和模型组成；标题优先显示服务名称与模型，正文身份卡补充协议。若历史结果没有 `reviewers`，才回退为“评审模型 A / 评审模型 B”，但绝不直接显示 `reviewer_a / reviewer_b`。

展开后首先显示固定身份摘要：评审模型、被评审模型、一句话结论、结论类型。结论类型只允许“认可、部分认可、不认可、无法判断”四种中文状态。

## 新任务输出结构

新交叉评审提示词要求模型直接输出以下 Markdown 结构，不输出“好的”“作为专家”等寒暄：

1. `结论摘要`：一句话说明是否认可被评审结果。
2. `认可之处`：只列有依据的正确判断。
3. `存在的问题`：列出逻辑、证据、市场需求或场景匹配问题。
4. `关键分歧`：明确评审模型与被评审模型在哪些方向或评分上不同。
5. `修正建议`：给出可以直接修改原分析的动作。
6. `最终推荐`：按优先级列出保留、降级或新增方向。

提示词必须明确传入评审模型和被评审模型的真实身份，要求使用第三人称模型名称，禁止使用 reviewer_a、reviewer_b、GPT、对方模型等模糊代称。输出限制重复论述，引用评论证据时保留来源标识，但不得虚构证据。

## 数据与兼容

保持现有交叉评审持久化结构和历史原文不变，不迁移、不改写历史任务。前端通过 `reviewers` 与结果键建立方向映射，因此当前任务刷新后即可显示真实标题。

新任务仍保存模型原始 Markdown；结构化展示从 Markdown 标题中提取内容。若某一模型未遵守结构，页面继续用现有 Markdown 渲染器展示，不导致任务失败。“查看模型原文”继续保留，作为核对与审计入口。

## 组件边界

- 新增纯函数负责：解析评审方向、格式化模型身份、生成标题。
- `CrossReviewPanel` 只负责折叠状态、摘要徽章和调用身份函数。
- 后端 `_build_cross_review_prompt` 只负责新输出契约和真实身份注入，不改变模型调用、计费、重试或供应商选择。
- 现有 Markdown 渲染器继续负责标题、段落、列表和表格，不引入新的富文本依赖。

## 异常处理

- 缺少 `reviewers`：显示“评审模型 A 评审评审模型 B”等中文安全回退。
- reviewer 数量不是两个：不猜测身份，显示“交叉评审结果”，原文仍可展开。
- 某方向评审失败：标题仍显示真实方向，正文显示该方向的脱敏错误。
- 历史键 `gpt_reviews_deepseek`：继续兼容，并优先使用已持久化真实身份覆盖旧固定名称。

## 测试与验收

- 单元测试覆盖 reviewer_a→reviewer_b、反向、旧 gpt/deepseek 键、缺失 reviewers 和任意供应商名称。
- 页面测试断言两个标题分别包含真实评审模型和被评审模型，并且方向正确。
- 后端提示词测试断言六段固定结构、真实被评审模型身份和禁止寒暄要求。
- 历史任务原始正文保持字节内容不变；刷新现有任务即可得到新标题。
- 完成后运行前端全量测试、TypeScript、生产构建，以及后端相关测试与全量回归。

## 非目标

- 不重新调用模型生成当前历史任务。
- 不自动修改两个模型的原始评分。
- 不自动选择、替换或增加付费模型。
- 不把自由文本强行解析成新的数据库字段。

## 回滚

回滚前端身份纯函数、面板接线、后端提示词及对应测试即可；历史数据和交叉评审原文不受影响。
