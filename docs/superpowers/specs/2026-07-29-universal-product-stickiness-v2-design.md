# 全品类高粘性组合推荐模型 V2.0 设计规范

**日期：** 2026-07-29

**状态：** 已确认，进入实施计划阶段

## 1. 目标

将当前偏向“同类目、同属性、同用户、同场景”的商品关联推荐，升级为面向全品类的消费者购买链路推荐。

新模型寻找的不是“看起来相关的商品”，而是消费者在购买、安装、使用、增强、维护、收纳、补充或复购过程中，愿意与主品一起购买的商品。

核心成功标准：

- 强依赖、规格兼容、消耗补充和连续任务组合稳定优先于弱场景组合。
- 同类目、同用户或同地点不能单独产生高分。
- 跨类目但存在真实购买关系的商品能够进入高推荐。
- 已包含、重复、不兼容的候选在评分前被淘汰。
- AI 不直接决定最终分数和等级；相同结构化输入产生相同程序评分。
- 推荐事实、AI 判断和待验证信息彼此分离，所有外部证据可以追溯。

## 2. 范围与边界

本次只优化组合判断逻辑，包括：

- 主品消费者任务和生命周期分析；
- 辅品候选生成与关系分类；
- 硬性淘汰规则；
- 四一致检查；
- 高粘性评分与排序；
- 市场证据分级、封顶和结果解释；
- 新结果的模型版本标识和全品类回归测试。

以下能力保持原样：

- 商品数据库；
- 关键词数据库；
- 已有商品和评论数据采集能力；
- 利润计算模块；
- API 供应商与模型选择机制；
- 历史任务的原始结果。

利润可以继续作为独立商业指标展示，但不得写入高粘性评分。旧任务不使用 V2.0 重新计算，不补造证据、分项分数或结论。

## 3. 全品类高粘性定义

同一次使用链路只是高粘性的一种，不是唯一条件。候选至少需要具备以下一种可说明、可验证的真实关系：

| 关系类型 | 定义 | 示例 | 默认强度 |
| --- | --- | --- | --- |
| 必需依赖 | 没有辅品时主品无法正常完成核心任务 | 打印机 + 对应墨盒 | 极高 |
| 规格兼容 | 辅品通过型号、尺寸、接口等明确适配主品 | 相机 + 匹配型号电池 | 极高 |
| 消耗补充 | 拥有主品会持续产生辅品补充或复购需求 | 咖啡机 + 咖啡胶囊 | 极高 |
| 连续任务 | 两件商品自然出现在同一次消费者任务中 | 研磨器 + 喷油壶 | 高 |
| 保护维护 | 辅品保护主品或维持其性能和寿命 | 皮鞋 + 护理剂 | 中高 |
| 效果增强 | 辅品明确增强主品结果，但主品可独立工作 | 麦克风 + 防喷罩 | 中高 |
| 收纳携带 | 辅品解决主品专用收纳、运输或整理问题 | 游戏机 + 专用收纳包 | 中等 |
| 风格/场合组合 | 消费者因共同场合或搭配目标购买 | 连衣裙 + 腰带 | 中等，必须加强市场验证 |
| 弱场景关联 | 只在同一地点或宽泛场景出现 | 床垫 + 卧室台灯 | 低 |
| 无有效关系 | 无法进入同一任务或生命周期 | 电动牙刷 + 吹风机 | 淘汰 |

关系类型不是商品类目。系统不得维护“厨房商品固定搭配表”作为主判断，也不得因为两个商品位于同一类目而加分。

## 4. 消费者任务与生命周期

系统首先识别消费者为什么购买主品，再把主品放入通用生命周期：

```text
购买 -> 安装/准备 -> 使用 -> 增强效果
     -> 保护维护 -> 收纳携带 -> 消耗补充 -> 再次购买
```

不同品类关注点不同，但使用同一套关系语义：

- 耗材型商品重点检查补充和复购；
- 电子设备重点检查型号、接口、安装和保护；
- 工具类重点检查任务连续性和效果增强；
- 服装家居重点检查尺寸、使用场合、风格和联购证据；
- 母婴、健康类增加年龄、安全和适用限制；
- 汽配增加车型、年份、零件号和规格兼容性。

这些差异用于要求相应事实，不改变统一的总分结构。系统按商品角色和关系类型工作，而不是针对某一个商品或类目写死规则。

## 5. 推荐流程与职责划分

```text
主品事实提取
-> 包装清单、规格和限制识别
-> 核心购买任务与生命周期拆解
-> 分关系类型生成候选
-> 程序执行硬性淘汰
-> 采集模块验证市场证据
-> 程序计算分数、封顶和等级
-> AI 根据已确定数据生成可读报告
```

### 5.1 AI 负责

- 提取主品核心购买任务；
- 识别包装内容、规格、适用对象和限制；
- 拆解消费者生命周期；
- 按关系类型生成候选；
- 输出关系假设、使用步骤、风险和待验证事项；
- 对需要语义判断的维度输出 0-5 级原始判断及逐项理由。

AI 不得直接给出最终 100 分、推荐等级、证据等级或封顶结果。

### 5.2 程序负责

- 校验 AI 结构化输出和必填字段；
- 检查已包含、重复、不兼容和无有效关系；
- 根据固定枚举和公式换算分数；
- 根据真实证据确定证据等级；
- 执行分数封顶、排序和最终推荐等级；
- 保存评分规则版本和计算明细。

### 5.3 采集与证据模块负责

- 保留来源平台、链接、查询词、采集时间和实际样本；
- 区分商品事实、搜索结果、竞品组合和交易证据；
- 不把搜索结果数量解释为销量；
- 不把单个竞品套装解释为普遍联购；
- 采集失败时返回明确状态，不允许 AI 补写来源或数据。

## 6. 候选生成

候选从三个入口产生：

1. 消费者任务链：完成同一任务还需要什么；
2. 商品生命周期：安装、使用、维护、补充或收纳需要什么；
3. 市场反向验证：平台是否存在明确组合关键词、套装、联购或交易证据。

候选池按关系类型探索，而不是按类目凑数量：

- 必需/兼容候选；
- 消耗复购候选；
- 连续任务候选；
- 效果增强候选；
- 保护维护候选；
- 收纳携带候选；
- 风格/场合候选。

某种关系没有合格候选时允许返回空列表。不得为了满足固定数量生成弱关联商品。每个候选必须有一个主要关系；可以记录次要关系，但同一事实不能在多个维度重复获得满分。

## 7. 硬性淘汰规则

硬性检查在评分前执行。出现以下任一情况时不得进入高推荐：

1. 主品包装已经包含该辅品；
2. 型号、尺寸、接口、年龄、车型、年份或适用对象不兼容；
3. 两件商品功能高度重复且没有新增价值；
4. 只有类目、用户、地点或宽泛场景一致；
5. 两件商品解决不同消费者任务，且生命周期没有连接；
6. 消费者不会自然产生联购心智，推荐必须经过复杂营销教育才能成立；
7. 无法指出辅品进入购买链路的具体步骤；
8. 商品安全或合规限制明确禁止该组合。

其中已包含、不兼容、安全限制属于直接淘汰。弱场景、营销教育成本过高等候选可以保留在审计数据中，但不能进入测试池。

## 8. 四一致检查

所有未被直接淘汰的候选必须保存四一致结果及理由：

- **用户一致：** 买主品的人是否自然也是辅品购买者；
- **场景一致：** 两件商品是否出现在同一个明确使用环境或目标中；
- **时间/生命周期一致：** 是否连续使用，或是否在安装、维护、补充等相邻生命周期阶段形成稳定连接；
- **心智一致：** 消费者看到组合后是否无需复杂解释便能理解一起购买的价值。

每项使用 0-5 级结构化判断。时间一致不强制要求同一分钟使用，依赖、补充和维护关系可以通过长期生命周期连接获得高判断。四一致是关系校验信息，不允许单靠“用户相同”和“场景相同”绕过真实关系门槛。

消费者模拟继续使用 A/B/C/D：

- A：自然一起购买；
- B：可能购买；
- C：需要营销教育；
- D：不合理。

模拟结果作为心智一致的解释输入，不能绕过程序评分或直接加减最终分。

## 9. 统一 100 分模型

所有品类使用同一总分结构：

| 维度 | 权重 | 核心问题 |
| --- | ---: | --- |
| 真实关系强度 | 30 | 是否存在依赖、兼容、补充、连续任务等明确关系 |
| 任务/生命周期连接 | 20 | 辅品是否自然进入主品消费者任务或生命周期 |
| 持续使用或复购价值 | 15 | 拥有主品后是否持续产生辅品使用或购买需求 |
| 功能增益 | 10 | 辅品是否明确提升主品结果、效率、保护或寿命 |
| 消费者自然联购 | 10 | 消费者是否无需教育便理解组合价值 |
| 市场验证证据 | 10 | 是否存在可追溯搜索、竞品或交易证据 |
| 用户与场景一致 | 5 | 目标用户和具体使用环境是否一致 |
| **总计** | **100** |  |

除市场证据外，结构化原始判断统一为 0-5 级，程序按 `原始判断 / 5 * 维度权重` 换算。市场证据分由证据等级映射，最终分由程序汇总并保留逐项原值、换算值和封顶原因。

类目相关性不单独加分，只参与商品理解和错误排除。

## 10. 证据分级与分数封顶

### 10.1 证据等级

| 等级 | 定义 | 允许的结论 |
| --- | --- | --- |
| E0 AI 推测 | 只有逻辑推演，没有外部证据 | 待研究方向 |
| E1 商品事实 | 商品页可验证包装、规格、功能或限制 | 事实已确认，市场关系未确认 |
| E2 搜索证据 | Amazon/Walmart 有明确组合搜索意图和有效结果 | 存在需求线索 |
| E3 竞品证据 | 多个独立竞品以套装、配件或组合形式销售 | 可以进入测试判断 |
| E4 交易证据 | 真实联购、订单或转化数据 | 可以支持重点开发判断 |

### 10.2 证据记录

每条证据至少保存：

- 证据类型和等级；
- 来源平台；
- 来源链接或数据标识；
- 采集时间；
- 实际使用的搜索关键词；
- 有效样本数；
- 支持或反对该组合；
- 可信度和失败状态。

页面必须将“已验证事实”“AI 判断”“待验证事项”分开显示。未取得的数据明确显示“未验证”，不得补写销量、评论、链接、样本数或消费者结论。

### 10.3 封顶规则

- 只有同类目或同场景：最高 49 分；
- E0：最高 59 分；
- E1：最高 69 分；
- E2：最高 79 分；
- E3：最高 89 分；
- E4：满足其他条件后才允许达到 90-100 分；
- 已包含、不兼容、功能重复或无有效关系：直接淘汰，不显示虚假高分。

封顶先于排序生效。页面同时显示原始计算分、证据封顶、最终分和封顶原因，避免用户误以为逻辑分等于市场验证结论。

## 11. 推荐等级与排序

```text
90-100：重点开发组合
80-89：进入测试池
70-79：观察验证
0-69：不推荐
```

排序使用封顶后的最终分。分数相同时依次比较：真实关系强度、证据等级、持续使用或复购价值、风险数量。不得使用类目相似度作为同分优先项。

## 12. 输出结构

每个新任务保存 `model_version: combination_model_v2.0`，并为每个候选输出：

- 辅品标准名称和可搜索精准关键词；
- 主要关系和次要关系；
- 消费者核心任务；
- 购买和使用链路；
- 商品生命周期位置；
- 四一致评分与逐项理由；
- 消费者模拟 A/B/C/D 与理由；
- 七维原始判断、换算分和计算公式；
- 硬规则检查结果；
- 证据等级、来源和采集状态；
- 原始计算分、封顶分、最终分和封顶原因；
- 风险、反对证据和缺失证据；
- 推荐等级与测试建议。

报告不再只显示产品名称和一个 AI 估算分。历史页面和任务详情必须消费同一份已保存结果，不能在前端重新评分。

## 13. 错误与降级处理

- AI 结构化输出缺失必填字段：允许有限次数重试；仍失败则任务明确标记该阶段失败，不生成默认高分。
- 候选关系无法归类：标记为无有效关系并进入审计记录，不进入推荐池。
- 商品包装或兼容事实不完整：标记待验证并执行对应证据封顶。
- 市场采集被登录、CAPTCHA、网络或页面结构拦截：保存失败原因，按现有证据等级封顶，不解释为“市场不存在需求”。
- 多个来源结论冲突：降低可信度，保留支持和反对证据，进入人工复核。
- AI 供应商切换：使用相同结构化契约；最终公式、封顶和等级不随供应商改变。
- 历史任务缺少 V2.0 字段：继续展示原结果并标记“旧模型结果”，不推测新字段。

## 15. 验收标准

### 15.1 规则正确性

- 强依赖、兼容和复购组合稳定排在弱场景组合之前；
- 同类目不能单独产生高分；
- 跨类目强关系可以获得高分；
- 已包含、重复和不兼容候选 100% 被拦截；
- 无市场证据时必定执行分数封顶；
- 每个最终分都能追溯到结构化输入、公式和证据。

### 15.2 稳定性

- 相同结构化输入重复计算得到完全相同的最终分和等级；
- 只改变兼容、包装内容或证据等级时，结果按规则单调变化；
- 当前自定义 Anthropic 风格供应商与 GPT 对同一输入提取的关键事实可以逐字段比较；
- 不同模型产生差异时，可以定位到具体事实或原始判断，不允许出现无法解释的随机总分。

### 15.3 当前研磨器案例

- Oil Sprayer 必须排在 Kitchen Scissors、Measuring Cups 和 Baking Mat 之前；
- Kitchen Scissors、Measuring Cups、Silicone Baking Mat 不得进入测试池；
- 包装已包含的 Spice Funnel 必须直接淘汰；
- Spice Rack 可以作为调味生命周期候选，但必须按证据等级封顶；
- 结果不得继续出现所有候选统一为 `convenience`、统一证据等级或 78-90 分拥挤的情况。

### 15.4 系统回归

- 商品数据库、关键词数据库、采集结果和利润计算不发生非预期变化；
- 任务详情、历史结果和导出使用相同的已保存 V2.0 数据；
- 旧任务可正常打开；
- 后端测试、前端测试、类型检查和生产构建通过；
- 使用真实自定义供应商完成至少一次端到端任务，并人工复核证据来源。

## 16. Git 与回滚

- 本设计规范使用独立提交；
- 后续实现按结构化契约、确定性规则、服务编排、前端展示、回归验证拆分提交；
- 每个阶段都可以通过 Git 单独回滚；
- 不提交 API Key、本地环境文件、运行日志和测试生成物；
- 实施前先形成详细开发计划，未经过书面规格复核不修改业务代码。
