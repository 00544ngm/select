# Walmart 真实采集恢复与任务页返回设计

## 目标

让桌面版对用户提供的 Walmart 商品链接完成真实商品采集、模型分析和报告生成；任务执行期间允许用户返回工作台，但不取消后台任务。只有指定真实链接完整生成报告后，才构建并交付覆盖安装包。

## 已确认问题

当前 Walmart 抓取器遇到 `/blocked` 或页面标题包含 `robot` 时，会在后台页面被动等待最多 300 秒，期望人工通过 CAPTCHA。桌面安装包不向用户展示该后台页面，因此用户无法完成验证，任务长期停在抓取阶段 5%，五分钟后才失败。模型在该失败路径中尚未调用。

## 交互设计

- `queued` 或 `running` 任务的进度卡片下显示“返回工作台”。
- 点击后导航到 `/`，不调用取消接口，不改变任务状态；用户可从历史记录重新进入任务详情。
- 抓取失败页面继续保留“重新提交”，并增加“返回工作台”。
- CAPTCHA 错误使用中文说明，明确区分“未抓取到商品数据”和“模型尚未调用”。

## 采集策略

先用指定真实链接复现并保存不含凭据的阶段证据，再针对阻断根因调整采集实现。允许的手段包括：

1. 使用桌面打包 Chromium 的持久化浏览器上下文与正常浏览器参数，减少每次任务使用全新会话带来的风控触发。
2. 优先解析 Walmart 页面可公开获得的结构化商品数据；结构化数据完整时不依赖易变化的可见 DOM 选择器。
3. CAPTCHA 确认无法自动恢复时快速、明确失败，禁止继续无意义等待 300 秒。

不绕过访问控制、不购买或接入未授权第三方数据、不伪造商品字段，也不在商品数据缺失时调用模型生成报告。

## 数据与任务流程

`用户链接 → Walmart 页面访问 → 商品字段完整性校验 → 模型分析 → 报告持久化 → 任务完成`

任一阶段失败都持久化准确的阶段错误。只有标题和价格等必填商品信息通过完整性校验后才进入模型分析。

## 测试与验收

- 前端测试：运行中显示返回按钮；点击导航到工作台；不会触发重试或取消；完成任务不显示运行按钮；失败页可返回。
- 抓取器测试：普通商品页解析成功；CAPTCHA 不再等待五分钟；缺少必填字段时禁止进入模型阶段。
- 回归：相关 Python 测试、前端 Vitest、TypeScript 检查和生产构建通过。
- 真实验收：使用用户提供的商品 `5257371669` 链接，实际抓取商品数据，并通过已勾选模型完成报告。报告必须持久化为 completed，包含真实主品标题/图片和至少一个分析结果。
- 交付门槛：真实验收未完成时不输出新安装包；完整链路成功后才重建 NSIS、启动整包冒烟验证并提供新 SHA-256。

## 安全与兼容

- 不在源码、文档、日志或安装包写入 API Key、Cookie 或会话令牌。
- 不修改旧任务结果；新任务使用当前已勾选且验证有效的模型。
- 覆盖安装保留用户本地配置和历史任务。
- 不恢复曾影响用户打字的可见辅助窗口或抢焦点方案。

## 非目标

- 不承诺第三方 Walmart 永久不改变反自动化策略。
- 不新增付费采集服务。
- 不实现任务取消功能。
