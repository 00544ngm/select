# CatToken 两个供应商彻底下线设计

## 目标

彻底停止 `cattoken`（CatToken OpenAI）与 `cattoken_claude`（CatToken Claude）被新配置、新任务或重试任务调用，同时保留历史任务结果的可读性。OpenAI、DeepSeek 与自定义供应商保持不变。

## 下线范围

1. API 设置页不再返回或展示两个 CatToken 槽位。
2. 工作台、对比审判、批量任务和交叉验证不再提供两个 CatToken 选项。
3. 新任务 DTO 不再接受两个 CatToken slug；后端 resolver 对旧客户端提交明确返回“供应商已下线”。
4. 数据库中两个 CatToken 配置记录及其加密 API Key 被删除；环境变量中的历史 CatToken 配置不再参与运行时回退。
5. 浏览器中各入口保存的 CatToken 偏好在加载时降级到 OpenAI，并覆盖为新的安全默认值。
6. 历史任务 payload、结果页供应商标签和历史导出不删除、不改写，仍可显示当时使用的 CatToken 名称。

## 数据与安全边界

- 只删除供应商配置表中 slug 精确等于 `cattoken` 或 `cattoken_claude` 的记录，不使用模糊匹配。
- 删除配置前先只读确认目标数量和 slug；不输出、解密或记录 API Key。
- 不删除任务、结果、日志、商品数据或其他供应商配置。
- 删除动作通过可重复执行的迁移/维护逻辑完成：目标不存在时安全跳过。

## 兼容策略

- 写入边界只允许 `openai`、`custom`（以及既有业务允许的其他非 CatToken 角色）；DeepSeek继续作为既有辅助模型使用。
- 历史读取边界继续把 `cattoken` 与 `cattoken_claude` 映射为原中文标签，避免旧结果出现内部 slug。
- 对旧浏览器缓存或旧客户端提交 CatToken，前端自动回退 OpenAI；绕过前端直接请求时后端拒绝，不静默改用其他付费供应商。

## 错误处理

- 新请求携带已下线 slug：返回稳定、可理解且不可重试的供应商下线错误。
- OpenAI 未配置时，不把 CatToken 作为回退；由现有“供应商未配置”流程处理。
- 正在运行的 CatToken 任务不强制中断；部署重启后的排队/重试任务按已下线规则拒绝，避免继续扣费。

## 验收

1. 设置接口与页面均不存在两个 CatToken 入口。
2. 所有任务入口和交叉验证选择器均不存在两个 CatToken 选项。
3. 后端 schema/resolver 拒绝新 CatToken 请求。
4. 数据库精确目标配置数量变为 0，其他供应商记录数量和内容保持不变。
5. 旧历史任务仍能打开并显示 CatToken 历史标签。
6. 后端测试、前端测试、类型检查、构建、Ruff、健康检查和浏览器实页验证通过。

## 回滚

代码回滚可恢复槽位与路由，但已删除的 API Key 不从日志或历史任务恢复；如未来重新启用，必须由用户重新录入密钥。
