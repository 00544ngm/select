# API 可视化配置与界面低眩光优化设计

日期：2026-07-27

## 1. 背景

当前系统从项目根目录 `.env` 读取 OpenAI、CatToken 和 DeepSeek 的 API 配置。修改密钥或模型需要直接编辑后端文件并重启相关进程。前端已经允许在任务高级选项中选择 OpenAI 或 CatToken 及其模型，但无法查看配置状态、替换密钥或验证连接。

当前界面以纯白背景和灰色边框为主。在宽屏工作台上，大面积空白造成较强眩光，导航和功能层级也不够突出。

## 2. 目标

1. 在前端新增独立的 API 设置页面，统一管理 OpenAI、CatToken、DeepSeek 和一个自定义 OpenAI 兼容 API。
2. API Key 只写、加密保存，任何读取接口、日志、任务历史和错误信息都不返回明文。
3. 配置保存后对后续任务立即生效，无需重启 API、Worker 或前端。
4. 保留现有 `.env` 配置作为首次迁移来源和兼容兜底，升级后现有任务流程仍可运行。
5. 全站采用已确认的“雾灰 × 墨绿”低眩光视觉方向，保持运营工具所需的清晰、稳定和高效率。
6. 通过后端、前端和端到端验证确保配置、提交任务、Worker 执行和结果展示保持正常。

## 3. 非目标

- 本次不增加账号、组织、多租户或按用户隔离的 API 配置。
- 本次只提供一个自定义 OpenAI 兼容 API 槽位，不实现任意数量的动态供应商。
- 本次不改变分析提示词、爬虫流程、评分规则、历史任务结构或结果业务内容。
- 本次不把 DeepSeek 改为工作台主模型。DeepSeek 继续承担现有的二次分析与交叉验证角色。
- 本次不删除 `.env` 中已有配置，也不自动清除用户现有密钥。

## 4. 已确认的产品决策

- 配置范围：单机全局配置，保存一次后所有任务共用。
- 支持范围：OpenAI、CatToken、DeepSeek、自定义 OpenAI 兼容 API。
- 存储方式：PostgreSQL 保存配置，API Key 使用后端本地密钥加密。
- 视觉方向：方案 A“雾灰 × 墨绿”。
- 导航方式：桌面端稳定展开，移动端使用抽屉；新增“API 设置”导航项。

## 5. 总体架构

```text
Next.js API 设置页
        |
        | 掩码读取 / 只写更新 / 连接测试
        v
FastAPI settings routes
        |
        | 校验、测试、加密、事务保存
        v
PostgreSQL provider_configurations
        ^
        | 任务开始时读取最新有效配置
        |
ARQ Worker -> Provider resolver -> OpenAI / CatToken / Custom
                         |
                         +----------> DeepSeek secondary（可选）
```

API 路由负责输入校验、连接测试和密钥加密。Worker 不再直接依赖进程启动时加载的 API Key，而是在任务被领取后通过配置仓库解析所需供应商。正在运行的任务继续使用已经创建的客户端；尚未开始的任务使用最新有效配置。

## 6. 数据模型

新增 `provider_configurations` 表，每个固定槽位最多一条记录：

| 字段 | 用途 |
|---|---|
| `id` | UUID 主键 |
| `slug` | 唯一值：`openai`、`cattoken`、`deepseek`、`custom` |
| `provider_type` | 客户端适配类型；自定义项使用 `openai_compatible` |
| `display_name` | 前端展示名称；内置项固定，自定义项可编辑 |
| `base_url` | 服务地址；OpenAI 可使用默认地址 |
| `default_model` | 默认模型名称 |
| `encrypted_api_key` | 加密后的 API Key，不参与接口序列化 |
| `api_key_last4` | 用于前端掩码标识，不足四位时不保存可识别片段 |
| `is_enabled` | 是否允许新任务使用 |
| `last_test_status` | `untested`、`success` 或 `failed` |
| `last_tested_at` | 最近测试时间 |
| `last_test_message` | 清洗后的测试摘要，不包含密钥或完整上游响应 |
| `created_at` / `updated_at` | 审计时间 |

`slug` 使用数据库唯一约束，避免并发保存产生重复配置。更新通过单事务完成；测试失败时回滚，不替换现有可用配置。

## 7. 密钥保护

1. 使用经审计的对称加密库保存 API Key，不自定义加密算法。
2. 优先从 `API_CONFIG_ENCRYPTION_KEY` 读取主密钥。未配置时，后端首次启动自动生成私有密钥文件 `backend/.api-config.key`，并尽可能限制为当前系统用户可读。
3. 私有密钥文件必须加入 `.gitignore`，不得写入数据库、前端资源、日志或测试快照。
4. API Key 是只写字段。`GET` 响应只返回 `configured`、`masked_api_key` 和最后测试状态。
5. 更新请求未提供 `api_key` 时保留原密钥。清除密钥必须使用显式 `clear_api_key`，避免空字符串误删。
6. 日志过滤常见密钥字段名，连接测试异常只返回清洗后的错误类别和用户可执行的提示。
7. 当前产品是本机单用户应用，设置接口只接受回环地址请求。未来开放局域网或公网访问前，必须新增管理员身份验证，不能仅依赖 CORS。

如果本地主密钥文件丢失，数据库内密钥无法恢复。系统应标记配置为“需要重新输入”，而不是输出解密异常或尝试使用损坏数据。

## 8. 后端 API

新增路由前缀 `/api/v1/settings/providers`：

### 8.1 读取配置

`GET /api/v1/settings/providers`

返回四个固定槽位的展示名称、Base URL、默认模型、启用状态、是否已配置、掩码 Key、测试状态和更新时间。响应模型不得包含 `encrypted_api_key` 或可逆密钥材料。

### 8.2 测试草稿

`POST /api/v1/settings/providers/{slug}/test`

请求可携带新的 Base URL、模型和 API Key；未提供 Key 时使用已保存密钥。测试不写数据库，不创建分析任务。测试使用极小的模型请求验证认证、地址和模型是否可用，并在 UI 上提示测试可能产生极少量模型费用。

### 8.3 保存配置

`PUT /api/v1/settings/providers/{slug}`

保存前执行字段校验。启用配置或变更 Key、Base URL、模型时，后端必须完成连接测试后才提交。禁用配置无需调用上游服务。失败返回结构化错误且保留旧配置。

### 8.4 错误代码

- `PROVIDER_NOT_CONFIGURED`：缺少可用密钥或必要字段。
- `PROVIDER_DISABLED`：任务选择了已停用供应商。
- `PROVIDER_AUTH_FAILED`：上游拒绝认证。
- `PROVIDER_MODEL_INVALID`：模型不存在或无权限。
- `PROVIDER_ENDPOINT_INVALID`：Base URL 不合法或不允许访问。
- `PROVIDER_UNAVAILABLE`：网络、限流或上游暂时不可用。
- `PROVIDER_CONFIG_DECRYPT_FAILED`：本地主密钥不匹配，需要重新输入 API Key。

错误响应继续使用项目现有统一错误结构，并明确 `retryable`。

## 9. URL 与请求安全

- 自定义 Base URL 默认要求 `HTTPS`。
- 开发模式可允许 `localhost` 和回环地址，便于使用测试服务。
- 拒绝包含用户名密码的 URL、链接本地元数据服务的地址、不可解析主机和明显的私网绕过形式。
- 连接测试设置严格超时，不跟随跨主机重定向，并限制响应体大小。
- Pydantic 请求模型禁止未声明字段，避免配置参数意外透传给上游客户端。

## 10. 配置解析与任务兼容

新增独立的 Provider Resolver，职责是根据任务中的 `provider` 和 `model` 创建客户端：

- `openai`：读取数据库 OpenAI 配置，缺失时使用现有 `.env` 设置。
- `cattoken`：读取数据库 CatToken 配置，缺失时使用现有 `.env` 设置。
- `custom`：只读取数据库自定义配置，没有 `.env` 兜底。
- `deepseek`：保持二次分析配置；缺失或停用时继续走现有单模型路径。

任务请求中的主供应商允许 `openai`、`cattoken`、`custom`。DeepSeek 不出现在主供应商下拉框中，但会在 API 设置页展示为“二次验证”。

现有结果载荷和历史页面保持兼容。若主供应商为 `custom`，可附加新的供应商元数据用于显示名称，但不得删除或重命名现有结果字段。交叉验证继续在主结果与 DeepSeek 结果之间运行。

## 11. 首次迁移与回退

1. 数据库迁移只新增表，不修改现有任务和产物表。
2. 首次启动时，如果数据库对应槽位为空且 `.env` 存在有效配置，则导入并加密保存。
3. 导入是幂等操作，不覆盖用户已在前端保存的数据库配置。
4. 原 `.env` 文件不删除。数据库中不存在对应配置时，内置供应商可回退到 `.env`；自定义供应商不回退。数据库已有配置但解密失败时不得静默使用旧 `.env` Key，必须标记为“需要重新输入”。
5. 升级部署需要一次性重启 API、Worker 和前端以加载新代码和数据库迁移。之后配置变更不需要重启。
6. 回退旧版本时，旧代码仍可继续读取保留的 `.env`，数据库新增表不会影响旧任务表。

## 12. 前端信息架构

### 12.1 导航

桌面端左侧导航稳定显示完整栏目：工作台、结果展示、历史记录、API 设置。导航宽度保持稳定，不因悬停改变主内容布局。移动端继续使用抽屉导航，并加入 API 设置入口。

### 12.2 API 设置页

路由：`/settings/api`

页面由以下区域组成：

1. 顶部状态摘要：显示已配置服务数量和整体可用状态。
2. 供应商标签：OpenAI、CatToken、DeepSeek、自定义 API。
3. 配置表单：显示名称（仅自定义）、Base URL、默认模型、API Key、启用状态。
4. 状态信息：掩码 Key、最近测试结果、测试时间和清洗后的错误提示。
5. 操作区：测试连接、保存配置；危险操作使用显式确认。

已有 Key 默认不渲染到输入框。用户点击“替换密钥”后才显示新的密码输入控件；取消替换不会改变已保存密钥。

### 12.3 工作台联动

工作台读取可用配置并仅列出已启用的主供应商。内置静态模型列表作为建议项保留，同时允许自定义配置使用手动模型名称。没有可用主供应商时，表单在提交前显示“前往 API 设置”，不创建必然失败的任务。

## 13. 视觉系统

采用“雾灰 × 墨绿”：

- 页面背景：低对比雾灰，减少宽屏纯白面积。
- 导航：深墨绿，提供稳定的应用边界。
- 内容表面：白色或极浅灰，用于表单、表格和结果模块。
- 主操作：中深墨绿，统一分析、保存和确认操作。
- 异常：珊瑚红，只用于失败、风险和不可逆操作。
- 成功与在线状态：柔和绿色；警告使用克制琥珀色。
- 圆角不超过 8px；表单和工作台保持紧凑，不使用营销页面式大标题或装饰性卡片。

通过 CSS 语义变量统一替换现有黑白令牌。工作台、历史表格、任务详情和结果模块共享同一套背景、边框、文字和状态色。保留现有背景图片功能，但默认主题本身必须在没有图片时具备完整层级。

## 14. 交互与可访问性

- 密钥输入使用密码控件，支持显示/隐藏图标并提供明确工具提示。
- 保存和测试均有独立加载状态，执行中防止重复提交。
- 成功、警告和失败同时使用图标、文字和颜色，不只依赖颜色表达。
- 标签、输入框、开关和按钮均支持键盘操作及可见焦点。
- 移动端字段改为单列，按钮文字不得被截断或与其他内容重叠。
- 网络失败保留用户尚未保存的表单内容。

## 15. 测试策略

### 15.1 后端

- 配置表仓库、唯一约束和事务更新测试。
- 加密、解密、掩码、主密钥丢失和错误密钥测试。
- API 响应不包含明文或密文字段的安全测试。
- 四个供应商的字段校验、启用/停用和测试连接错误分类。
- `.env` 首次导入、幂等性、数据库优先级和回退测试。
- Worker 对 OpenAI、CatToken、自定义主模型和可选 DeepSeek 二次模型的解析测试。
- 自定义 Base URL 的 SSRF、重定向、超时和响应大小限制测试。

### 15.2 前端

- API 设置页读取、掩码显示、替换密钥、测试、保存和失败保留测试。
- 四个供应商标签及 DeepSeek“二次验证”角色提示测试。
- 工作台仅展示已启用主供应商、无配置提示和自定义模型输入测试。
- 桌面导航、移动抽屉、键盘焦点和可访问名称测试。
- 全站主题令牌和关键页面基础渲染回归测试。

### 15.3 端到端与验收

端到端测试使用本地模拟 OpenAI 兼容服务，不调用真实 API：

1. 打开 API 设置页并保存模拟配置。
2. 验证前端只能看到掩码 Key。
3. 测试连接成功后在工作台选择该供应商。
4. 提交任务并验证 Worker 使用数据库配置创建客户端。
5. 验证任务状态、错误映射和结果页面保持兼容。
6. 保存无效配置时验证旧配置仍然可用。

完成前运行后端测试、前端单元测试、TypeScript 类型检查、生产构建和现有关键端到端测试。最后在桌面与移动视口检查导航、表单、加载状态、错误状态和文本溢出。

## 16. 验收标准

- 用户不编辑后端文件即可查看、测试、保存、替换、启用或停用 API 配置。
- API Key 在浏览器响应、日志、任务记录和错误信息中始终不可见。
- 新配置保存后，无需重启即可被下一个开始执行的任务使用。
- 现有 `.env` 配置可自动迁移，旧任务与结果页面不受影响。
- OpenAI、CatToken 和自定义 API 可作为主模型；DeepSeek 保持二次验证角色。
- 无有效供应商时，任务在前端提交前被阻止并提供 API 设置入口。
- 全站默认不再呈现大面积纯白背景，桌面与移动端均无控件重叠或文字截断。
- 所有新增测试与现有相关测试通过，生产构建成功。

## 17. 风险与缓解

- **本地主密钥丢失**：配置不可解密；显示“需要重新输入”。`.env` 仅保留为人工回退来源，不在解密失败时静默启用。
- **上游兼容差异**：自定义 API 明确限定 OpenAI 兼容格式，通过连接测试提前发现差异。
- **配置更新影响排队任务**：任务开始时读取最新配置；UI 明确说明新配置影响尚未开始的任务。
- **测试请求产生费用**：使用极小请求并在按钮附近明确提示。
- **本地设置接口被网页滥用**：限制回环请求、保持严格 CORS，并拒绝不可信 Base URL。未来远程部署必须增加管理员认证。
