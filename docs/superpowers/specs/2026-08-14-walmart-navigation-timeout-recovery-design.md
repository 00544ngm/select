# Walmart 导航超时与人工验证恢复设计

日期：2026-08-14

状态：待用户审核

## 背景

当前 Walmart 商品抓取在 `page.goto(..., wait_until="domcontentloaded", timeout=30000)` 超时时，会被包装为通用 `SCRAPE_FAILED`。导航超时发生在验证码检测之前，因此 Walmart 的 `Robot or human?`、网络连接卡住、代理/DNS 失败和普通页面响应异常无法区分。截图中的 Claude 模型尚未执行，模型轮换不能解决这个阶段的问题。

## 目标

- 识别 Walmart 反爬验证、页面导航超时、网络连接失败和浏览器进程异常。
- 检测到验证或疑似拦截时，自动从无头浏览器切换到可见浏览器。
- 员工完成验证后继续当前商品抓取，不重新创建任务，不调用模型。
- 验证等待期间任务保持运行，验证超时后给出专用错误和重新提交入口。
- 不记录 API Key、Cookie、Authorization、完整页面 HTML 或完整商品原文。
- 不把抓取阶段失败交给 GPT/Claude 模型轮换，不修改历史任务数据结构。

## 非目标

- 不绕过、破解或自动完成 Walmart 验证。
- 不伪造商品数据绕过抓取失败。
- 不用无限延长 `page.goto` 超时时间掩盖网络问题。
- 不修改模型供应商、模型验证、报告生成或 Token 计费逻辑。

## 运行流程

```text
创建无头页面
  -> 以较短导航窗口打开 Walmart
  -> 成功加载：检查页面内容并继续抓取
  -> 检测验证页或导航超时但页面仍可访问：切换可见浏览器
  -> 更新任务为“等待 Walmart 验证”
  -> 员工完成验证
  -> 重新打开同一商品地址并继续抓取
  -> 验证超时：返回 WALMART_CAPTCHA_TIMEOUT
```

页面导航未建立连接或明确为网络错误时，最多执行一次带退避的导航重试；重试仍失败时返回专用导航错误，不自动切换模型。

## 检测与错误分类

### 验证/拦截信号

只记录布尔结果和异常类型，不记录页面全文。检测信号包括：

- 当前 URL 包含 Walmart blocked/verification 路径。
- 页面标题或有限文本包含 `Robot or human?`、验证码或验证提示。
- HTTP 响应状态为反爬相关状态，且页面没有可用商品 DOM。
- 导航超时后页面仍存在，并可读取标题、URL 或有限的验证标记。

命中上述信号才抛出内部 `WalmartCaptchaRequiredError`，由现有可见浏览器恢复流程处理。

### 导航错误

新增稳定错误分类，建议使用以下错误码：

- `WALMART_NAVIGATION_TIMEOUT`：没有检测到验证码信号，页面在导航窗口内未完成。
- `WALMART_NETWORK_FAILED`：DNS、连接重置、代理或 TLS 连接失败。
- `WALMART_CAPTCHA_TIMEOUT`：已打开可见浏览器，但员工未在等待上限内完成验证。
- `BROWSER_TARGET_CLOSED`：浏览器页面或进程被关闭，沿用现有恢复逻辑。

所有错误消息只包含阶段、错误类别和操作建议，不包含完整 URL 查询参数、Cookie 或页面原文。

## 组件边界

### Walmart 抓取器

- 将导航动作与页面内容检测拆成两个可测试步骤。
- 导航使用有限的初始响应窗口；成功建立页面后单独等待内容/验证状态。
- 导航超时时保留当前页面用于验证信号检测，随后安全关闭页面。
- 复用现有 `restart_visible`、`verification_status` 和人工等待机制。
- 验证成功后只重试当前商品抓取，不重新提交任务、不创建模型 attempt。

### Worker

- 抓取错误在 `scrape` 阶段持久化稳定错误码。
- `WALMART_CAPTCHA_TIMEOUT`、`WALMART_NAVIGATION_TIMEOUT` 和 `WALMART_NETWORK_FAILED` 不进入 AI 模型轮换。
- 等待验证期间不调用 Provider Resolver，不写模型调用记录。

### 前端

- 展示“正在等待 Walmart 验证”“请在弹出窗口中完成验证”“验证成功，继续抓取”等状态。
- 导航超时显示网络/代理/安全软件排查建议。
- 验证超时显示重新提交按钮。
- 不展示内部堆栈、完整 URL、Cookie 或浏览器路径。

### 桌面浏览器管理器

- 可见浏览器必须使用当前安装包内的 Chromium 和当前用户数据目录。
- 切换和关闭时只清理当前任务创建的页面/进程。
- 保留现有浏览器进程健康检查和零残留验收。

## 数据与 Token 边界

- 不新增数据库表或修改历史任务结构；复用现有任务状态、错误码和验证状态字段。
- 抓取阶段未完成前不调用 Claude、GPT 或其他模型，因此不消耗报告 Token。
- 等待人工验证不发送模型请求。
- 日志禁止写入 API Key、Authorization、Cookie、完整 HTML、完整 Prompt 和完整模型输出。

## 测试设计

先写失败测试，再实现最小改动：

- 导航超时且页面为验证页时，触发 `restart_visible` 并更新验证状态。
- 普通网络超时不误判为验证码，返回 `WALMART_NAVIGATION_TIMEOUT` 或 `WALMART_NETWORK_FAILED`。
- 验证完成后继续同一商品抓取，且只产生一次抓取流程。
- 验证超时返回 `WALMART_CAPTCHA_TIMEOUT`，不创建模型 attempt。
- 抓取阶段错误不会触发模型轮换。
- 现有 Walmart/Amazon 抓取、历史记录、模型轮换和 Worker 回归保持通过。
- 前端专用状态和错误建议测试通过。
- 使用特殊字符员工路径启动最终安装包，验证 API、Worker、可见浏览器切换、数据库和零残留进程。

## 验收标准

- 员工电脑遇到截图类 Walmart 超时时，不再只显示通用 `SCRAPE_FAILED`。
- Walmart 验证页可自动切换到可见浏览器，人工完成验证后任务能继续。
- 网络故障能显示网络类错误，且不会误导员工进行 AI 模型适配。
- 等待验证和抓取失败均不调用模型、不产生额外 Token。
- 正常抓取、历史页面、已有模型轮换和现有第三方 OpenAI/Anthropic 接入不回归。
- 安装包关闭后本次任务创建的进程残留为 0。

## 回滚

删除本规格及后续新增代码即可回滚设计变更；不执行数据库降级，不覆盖旧安装包，不修改真实用户数据库、历史任务或供应商密钥。
