# Windows 原生桌面安装版设计规格

## 1. 目标

将当前由 Next.js、FastAPI、PostgreSQL、Redis/ARQ 与 Playwright/Chromium 组成的本地 Web 软件，改造为可在公司多台 Windows 电脑上独立安装和运行的桌面软件。

最终用户只需运行中文安装包并双击“组合选品控制台”图标，不需要自行安装 Python、Node.js、PostgreSQL、Redis、Docker 或浏览器驱动。

## 2. 已确认的产品约束

- 目标平台：Windows 10/11 64 位。
- 分发范围：公司多台 Windows 电脑。
- 数据模式：每台电脑数据独立，不通过局域网共享。
- 当前电脑升级：旧版历史任务、分析结果、任务名称、状态、模型验证记录和供应商配置全部自动迁移。
- 后台行为：关闭主窗口时缩小到系统托盘，任务继续运行。
- 更新方式：首版不自动更新，使用新版安装包手动覆盖安装。
- 安装权限：允许管理员权限安装。
- 技术路线：Electron + FastAPI + SQLite + 本地持久化任务队列。
- 旧任务边界：只迁移和展示已保存结果，不重新调用模型，不改写历史结论。

## 3. 不在首版范围内

- macOS、Linux、Windows 7 与 32 位 Windows。
- 多台电脑共享任务、历史记录、数据库或 API 配置。
- 云端账户、云同步、在线自动更新与静默更新。
- 多任务并行执行。
- 为桌面化目的重写现有分析算法、评分规则或全品类业务逻辑。
- 迁移完成后自动删除旧 PostgreSQL 数据或旧版程序。

## 4. 总体架构

### 4.1 Electron 桌面宿主

Electron 负责：

- 主窗口与应用菜单。
- 系统托盘。
- 单实例锁。
- 本地服务启动、健康检查、异常监控与安全停止。
- 用户数据目录定位。
- 安装、覆盖升级与卸载生命周期。

再次双击图标时不启动第二套服务，而是唤醒已有窗口。

### 4.2 前端

保留现有 Next.js 页面和交互。生产构建结果作为安装包资源，由 Electron 窗口加载，不再要求用户打开普通浏览器。前端继续通过稳定的 API 契约访问 FastAPI。

### 4.3 后端

保留 FastAPI 和现有 Python 分析业务。后端只监听回环地址，并由 Electron 分配或协商本地可用端口。端口不对局域网暴露，桌面宿主在健康检查完成前不展示业务主界面。

### 4.4 数据库

用 SQLite 替换桌面运行时 PostgreSQL。数据库文件位于当前 Windows 用户的数据目录，而不是安装目录。数据库访问层需要保留清晰接口，使迁移期间 PostgreSQL 与 SQLite 能运行同一组领域和 API 测试。

SQLite 必须启用适合单机应用的事务、外键、忙等待和 WAL 配置。数据库写入由明确事务保护，不依赖桌面窗口是否可见。

### 4.5 本地任务队列

用 SQLite 持久化任务队列替换 Redis/ARQ。独立 Python Worker 默认一次只领取一个任务。队列领取使用原子状态转换，避免同一任务被重复执行。

队列必须保存：排队时间、开始时间、执行阶段、进度、尝试次数、取消请求、中断状态、完成时间和脱敏错误信息。

### 4.6 商品抓取

Playwright 与固定版本 Chromium 随安装包部署。抓取组件从桌面资源目录解析浏览器位置，不依赖用户电脑已安装的 Chrome，也不在线临时下载浏览器。

## 5. 进程与生命周期

Electron 主进程负责启动和监督：

1. FastAPI 本地服务。
2. 单并发 Python Worker。

启动顺序为：获取单实例锁 → 初始化用户数据目录 → 检查或迁移数据库 → 启动后端 → 启动 Worker → 验证数据库、契约和抓取组件 → 显示主界面。

Worker 意外退出时，Electron 自动重启一次；连续失败后停止重启，显示中文诊断信息，防止无限重启循环。

关闭主窗口只隐藏到托盘。托盘至少提供：打开主界面、当前任务状态、完全退出。

完全退出时停止接收新任务。如果有正在执行的任务，用户可以选择“缩小到托盘继续运行”或“安全停止并退出”。安全停止会记录取消请求，等待当前不可中断的网络步骤结束，再保存状态并关闭 Worker 和后端。

## 6. 任务状态与异常恢复

- 新任务必须先持久化，之后才能进入执行器。
- 排队任务可取消，取消后不能被 Worker 领取。
- 正在执行的任务取消时进入“正在安全停止”。
- 软件或电脑异常关闭后，排队任务继续保留。
- 启动时发现旧的运行中任务，标记为“异常中断，可重新提交”，不从未知中间点盲目续跑。
- 任务只有在结果结构完整并通过现有质量校验后才能标记完成。
- API、模型、抓取、解析、数据写入和桌面运行环境错误必须分别分类，并显示中文原因与下一步。
- 不得把所有异常统一折叠为“内部错误”。

## 7. 数据迁移

### 7.1 迁移内容

当前电脑首次安装时迁移：

- 历史任务及任务名称。
- 任务状态、进度与时间信息。
- 已保存分析结果和报告数据。
- 供应商配置与模型验证记录。
- 必要的本地附件与可定位资源。

其他公司电脑全新安装时创建独立空数据库，不复制当前电脑数据或 API Key。

### 7.2 迁移流程

1. 检测旧版 PostgreSQL 和旧配置。
2. 创建迁移前完整备份和迁移清单。
3. 以只读方式导出旧数据。
4. 转换并写入临时 SQLite 数据库。
5. 校验表、任务、结果和供应商配置数量。
6. 抽查历史任务详情可读性。
7. 原子切换为正式 SQLite 数据库。
8. 生成不含密钥和模型正文的迁移报告。

迁移成功前不得修改或删除旧 PostgreSQL 数据。迁移失败时删除或隔离未完成的新数据库，恢复到迁移前状态，旧版继续可用。

### 7.3 历史结果保护

迁移只改变存储介质，不重新抓取商品、不调用模型、不修改评分、不重写历史结论。旧任务缺少新字段时继续使用现有兼容展示逻辑。

## 8. API Key 与本地安全

- API Key 使用 Windows DPAPI 按当前 Windows 用户加密。
- SQLite 只保存加密密文或密钥引用，不保存可直接读取的明文。
- 日志、错误报告、迁移报告和备份摘要不得输出完整密钥。
- 本地后端仅绑定回环地址。
- Electron 与后端使用每次启动生成的本地会话凭据，避免其他本机网页直接调用业务接口。
- 调试端口和开发者工具默认关闭。
- 完整退出时清理会话凭据和临时文件，但不删除用户数据。

## 9. 备份、恢复与升级

- 用户数据与安装文件分离。
- 首次迁移和每次覆盖升级前自动备份。
- 默认保留最近 5 份备份。
- 设置页提供“立即备份”和“从备份恢复”。
- 恢复前再创建当前状态保护备份。
- 覆盖升级流程：停止接收任务 → 继续等待或安全停止 → 备份 → 替换程序 → 执行数据库迁移 → 健康检查 → 启动新版。
- 升级失败时保留原数据库和备份，不允许半迁移数据库进入正常运行。
- 首版不实现联网自动更新。

## 10. 安装与卸载

使用 Electron Builder 与 NSIS 生成中文管理员安装包，例如：

`组合选品控制台-Setup-1.0.0.exe`

安装包包含 Electron、前端资源、独立 Python 运行环境、FastAPI、Worker、Playwright Chromium、SQLite 迁移工具和必要运行库。

安装时可选择目录，并创建桌面和开始菜单快捷方式。正常运行不显示 PowerShell、CMD 或 Python 控制台窗口。

卸载默认保留用户数据库、密钥密文、附件和备份；只有用户明确勾选“同时删除个人数据”时才删除。执行删除前必须显示数据范围和不可恢复提示。

## 11. 错误处理与诊断

启动失败时显示中文诊断窗口，至少包含：失败组件、错误类别、建议动作、复制脱敏诊断信息、打开日志目录。

诊断信息不得包含 API Key、Cookie、完整模型提示词、模型完整回复或不必要的商品隐私数据。

关键错误类别包括：数据库迁移失败、数据库锁定、后端启动失败、Worker 启动失败、Chromium 缺失、端口不可用、API 认证失败、模型不可用、抓取失败和结果结构校验失败。

## 12. 分阶段实施

### 阶段一：SQLite 数据层兼容

- 建立 SQLite 配置和访问适配。
- 保留 PostgreSQL 运行能力用于迁移验证。
- 让同一组 repository、API 与领域测试覆盖两种数据库。
- 编写只读导出、转换、校验和回滚工具。

### 阶段二：本地持久化任务队列

- 新建任务领取、取消、中断和恢复机制。
- 保持现有任务 API 和页面行为。
- 移除桌面运行时对 Redis/ARQ 的强制依赖。

### 阶段三：Electron 桌面外壳

- 建立主窗口、托盘、单实例和进程监督。
- 接入本地会话认证和安全退出。
- 将生产前端装入桌面窗口。

### 阶段四：安装、迁移与恢复

- 生成 NSIS 安装包。
- 在当前电脑执行只读迁移演练。
- 在干净 Windows 10/11 电脑验证全新安装。
- 验证覆盖升级和卸载保留数据。

### 阶段五：完整验收与发布

- 完成自动化、安装机和迁移验收。
- 生成中文安装说明、备份恢复说明和版本变更记录。
- 发布首个可回退安装版。

## 13. 验收标准

- 干净 Windows 10/11 64 位电脑无需开发环境即可安装和启动。
- 前端、后端、Worker、SQLite 与 Chromium 健康检查全部通过。
- 当前电脑旧任务、结果和配置数量迁移一致，历史详情可打开，旧任务不产生新 Token。
- 三种任务入口均可提交、排队、执行和输出。
- OpenAI、DeepSeek、自定义 OpenAI 兼容与 Anthropic 兼容接口保持可用。
- Walmart 商品抓取与本地 Chromium 正常。
- 关闭窗口后托盘继续执行任务；完全退出能安全停止。
- 异常重启后排队任务不丢失，运行中任务被明确标记为可重新提交。
- 历史记录、任务改名、商品图片与 ID、交叉评审和中文结果保持正常。
- API Key 在数据库、日志、备份摘要和迁移报告中均不以明文出现。
- 覆盖升级保留数据并有失败回滚；卸载默认保留个人数据。
- 软件不会启动第二实例，也不会把后端暴露给局域网。

## 14. 测试策略

- 数据层契约测试：PostgreSQL 与 SQLite 对同一 repository 行为一致。
- 迁移测试：空库、正常库、缺少可选字段、重复迁移、迁移中断和校验失败。
- 队列测试：原子领取、单并发、取消、Worker 崩溃、电脑异常中断和重复启动。
- 安全测试：DPAPI 加解密、密钥脱敏、回环绑定、本地会话认证和日志扫描。
- 桌面测试：单实例、托盘、窗口恢复、完全退出和子进程清理。
- 安装测试：全新安装、覆盖安装、卸载保留数据和显式删除数据。
- 业务回归：现有后端和前端全量测试、生产构建与关键实页流程。
- 真实环境验收：至少一台升级电脑和一台干净 Windows 电脑。

## 15. 回滚边界

每个阶段必须独立可回滚。数据库正式切换前保留旧数据库和备份；队列替换前保留现有任务 API 契约；Electron 只作为宿主，不改变分析结果协议。任何迁移或升级失败都不得删除旧数据、覆盖历史结果或自动切换到其他付费模型。
