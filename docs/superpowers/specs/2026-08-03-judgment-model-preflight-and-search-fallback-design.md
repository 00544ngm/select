# 对比审判模型预检与搜索降级设计

日期：2026-08-03

## 目标

修复两个相互独立但都发生在工作台的故障：

1. 对比审判仍能提交中转站已经下线的历史已验证模型，任务抓取完成后才在模型阶段失败。
2. 搜索商品在桌面模式下没有使用动态 API 地址与会话令牌，且 Walmart 搜索页被机器人验证拦截时只返回模糊失败。

## 设计原则

- 不根据 24 小时历史快照假定中转站路由持续可用。
- 不静默替换员工明确选择的模型。
- 不把空搜索结果冒充成功。
- 不引入未经授权的第三方 Walmart 数据源。
- 不要求用户配置新的 Walmart Marketplace 卖家令牌。
- 失败必须尽早、中文、可操作，并更新界面状态以避免重复犯错。

## 对比审判数据流

### 提交前实时预检

所有分析入口继续通过 `JobService` 的统一模型可用性检查。`ProviderService.is_model_available` 在确认供应商启用、密钥存在、模型已勾选且历史验证未过期后，再使用现有 `ProviderModelVerifier` 发起一次最小结构化探测。

- 探测成功：刷新验证时间，保持勾选，允许创建任务。
- 模型不存在、404 或当前分组无路由：写入 `unavailable`，取消该模型勾选，拒绝本次提交。
- 认证失败：写入不可用状态并拒绝提交，但不删除密钥。
- 限流、502/503、超时等临时错误：写入 `temporary_error`，拒绝本次提交并允许用户稍后重试。

任务只有在实时预检通过后才写入队列，因此失效模型不会先抓取商品、消耗数分钟后才失败。

### 工作台刷新

对比审判提交收到模型不可用错误时，前端使供应商查询失效并重新加载。模型目录更新后：

- 已失效模型从可选列表消失。
- 该入口保存的失效偏好被判定为无效。
- 如果还有其他已勾选且验证成功的模型，自动显示第一项；不会自动提交。
- 如果没有模型，显示“前往 API 设置”。

### Worker 防御

提交与执行之间仍可能发生上游路由变化。Worker 遇到明确的 model-not-found/route-unavailable 时，同样把验证记录标记为不可用并取消勾选，再保存任务失败。这是第二层防御，不负责静默换模型。

## 搜索商品数据流

### 桌面 API 修复

`SearchForm` 不再自行拼接 `localhost:8000`，统一调用 `frontend/lib/api/search.ts` 的 `searchWalmart`，由 `apiFetch` 注入 Electron 动态 API 地址和 `X-Desktop-Session`。

### Walmart 机器人验证

后端识别搜索页标题或 `/blocked` 地址，返回稳定错误码 `WALMART_SEARCH_REQUIRES_BROWSER` 和中文说明，而不是通用 `SEARCH_FAILED`。

前端收到该错误后显示：

- Walmart 要求人工验证，应用内无法读取搜索结果。
- “在浏览器打开 Walmart 搜索”链接，查询词经过 URL 编码。
- 用户可在正常浏览器完成验证、复制商品链接，再回到对比审判使用。

其他网络错误继续显示 `SEARCH_FAILED`，不误导为机器人验证。

## 接口与状态变更

- 不新增数据库迁移。
- 不改变现有搜索成功响应 `{ results: [...] }`。
- 搜索机器人验证使用 HTTP 409 与稳定 detail code。
- 模型实时预检复用现有验证记录表和选择字段。
- 旧任务结果保持只读，不回写历史分析。

## 测试策略

### 后端

- 已勾选且历史验证新鲜，但实时探测返回 model-not-found：提交检查返回 false、验证状态变为 unavailable、勾选被取消。
- 实时探测成功：提交检查返回 true、验证状态保持 verified 与 selected。
- Worker 执行期间遇到模型路由失效：持久化模型失效状态。
- 搜索页出现机器人验证：返回 409 与 `WALMART_SEARCH_REQUIRES_BROWSER`，并关闭页面和上下文。
- 普通搜索成功与一般网络错误行为不回归。

### 前端

- 搜索表单通过统一 `searchWalmart` 客户端提交准确关键词。
- 机器人验证错误显示中文说明和编码后的 Walmart 搜索链接。
- 对比审判模型错误后刷新供应商目录，不继续保留失效选择。
- 既有三入口独立模型偏好保持不变。

### 真实验收

- 使用当前配置的失效 Claude 模型提交时，在创建任务前得到明确错误，并从工作台选项移除。
- 选择仍可用模型后，对比审判至少完成一条真实 A/B 链路。
- 搜索关键词真实触发 Walmart 拦截时显示外部搜索入口；若环境允许正常返回结果，则结果卡片仍可选择为 B 品。
- 后端、前端全量测试、类型检查、生产构建、安装包整包启动均通过后才交付。

## 安全与回滚

- 实时探测使用现有加密配置，日志和错误中不输出 API Key。
- 不记录用户提供过的明文密钥。
- 回滚只需恢复本轮服务、Worker、搜索路由与前端表单文件；无数据库结构变化。
