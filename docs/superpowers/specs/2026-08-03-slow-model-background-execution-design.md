# 慢模型后台执行与可见等待时间设计

## 目标

允许 OpenAI 5.5 系列模型拥有足够的完整报告生成时间，同时避免自动重试造成重复 Token 消耗；用户可以在任务运行期间返回工作台，稍后从历史记录查看结果。

## 已确认方案

- `gpt-5.5`、`gpt-5.5-pro` 及带日期后缀的同系列模型，完整结构化报告单次等待上限设为 600 秒。
- 其他模型继续使用现有 120 秒上限；已通过完整报告验收的 `gpt-5.4` 仍为推荐模型。
- 完整报告调用保持 `max_retries=1`，即最多发起一次模型请求。超时后明确结束任务，不自动重复请求。
- 任务继续由现有 Worker 在后台运行。详情页轮询任务状态并显示“已等待 X 分 X 秒”；用户点击“返回工作台”只离开当前页面，不取消后台任务。
- 运行提示明确说明：关闭详情页不会停止任务；模型仍可能在供应商侧处理；超时不会自动重试。

## 数据流

1. Worker 解析任务选择的供应商和模型。
2. LLM 客户端根据规范化后的模型名称选择 120 秒或 600 秒单次时限。
3. 任务详情页使用任务创建/开始时间计算动态等待时长，不新增数据库字段。
4. Worker 完成时沿用现有成功报告流程；超时时写入包含模型名和实际时限的稳定错误代码。
5. 用户从工作台或历史记录重新进入任务详情即可查看最终状态。

## 错误处理

- 600 秒到期仍无完整响应：返回 `PROVIDER_MODEL_TASK_TIMEOUT`，不再次请求模型。
- 网络或供应商提前返回错误：沿用现有分类，不错误地等待到 600 秒。
- 用户离开详情页：不改变任务状态，不中断 Worker。
- 应用退出：沿用持久化队列和现有恢复机制，本次不扩展为远程服务器任务。

## 界面

- 运行中进度卡新增动态文字：`模型正在生成完整报告，已等待 2 分 18 秒`。
- 5.5 系列额外显示：`慢模型最长等待 10 分钟，超时不会自动重试。`
- 保留现有“返回工作台”按钮，并补充：`返回后任务继续在后台运行，可在历史记录查看。`
- 本轮不增加“强制取消”按钮；当前上游请求未必支持可靠撤销，按钮可能让用户误以为供应商已停止计费。

## 测试与验收

- 单元测试先证明 5.5 系列选择 600 秒、其他模型选择 120 秒、结构化请求仍只有一次。
- 前端测试先证明运行中显示动态等待信息及返回工作台说明。
- 后端、前端和桌面全量回归通过后重新构建安装包。
- 使用真实 5.5 模型做一次最长 10 分钟的端到端观察；无论成功或超时，都必须确认没有第二次模型请求。
- 使用 `gpt-5.4` 再跑一条真实报告，确认既有稳定路径未回归。

## 边界

- 不承诺 5.5 一定在 10 分钟内完成；本功能的目标是给它合理时间并让过程可见。
- 不把 API Key 写入源码、日志、报告、设计文档或安装包。
- 不改变 Maike 当前因完整报告 JSON 不稳定而被阻止用于正式任务的结论。
- 按用户要求不执行 Git 提交、分支、合并或清理操作。
