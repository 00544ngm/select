# 历史任务名称行内编辑设计

## 目标

允许用户在“历史记录”列表直接补充或修改任务备注名称，解决任务创建时忘记命名后只能长期显示“未命名任务”的问题。该功能只修改任务的 `name` 字段，不改变任务状态、分析结果、评分、商品数据、供应商、模型或任务 ID。

## 交互设计

每条历史记录的任务名称右侧增加一个“修改备注”图标按钮。点击后，当前名称原位切换为单行输入框，并显示“保存”和“取消”按钮：

- Enter 或“保存”提交；Esc 或“取消”恢复原值。
- 输入框自动获得焦点并选中现有名称，方便直接替换。
- 名称去除首尾空格，最多 100 个字符。
- 空字符串允许保存，后端持久化为 `null`，列表重新显示“未命名任务”。
- 保存期间只禁用当前行的编辑控件，不阻塞其他任务。
- 保存成功后立即更新 React Query 中的历史列表缓存，无需刷新页面。
- 保存失败时保持编辑状态和已输入内容，在当前名称下显示中文错误，并允许再次保存或取消。

任务详情跳转仍由商品缩略图、任务名称和主品信息区域承担；编辑按钮不嵌套在链接中，点击编辑、保存或取消都不会跳转详情页。其他行同时保持只读；为避免误操作，同一时间只允许编辑一条任务。

## 后端接口

新增 `PATCH /api/v1/jobs/{job_id}/name`，请求体为：

```json
{ "name": "补充的任务备注" }
```

响应沿用 `JobSummary`。新增 `JobNameUpdate` schema：`name` 可为字符串或 `null`；字符串在验证时执行 `strip()`，空字符串转换为 `null`，非空值限制为 100 个字符。

`JobRepository.rename(job_id, name)` 只更新 `analysis_jobs.name`、`version + 1` 和 ORM 的 `updated_at`，并返回更新后的任务。任务不存在时接口返回现有风格的 404 `JOB_NOT_FOUND`；请求超过长度时由 FastAPI/Pydantic 返回 422。所有 queued、running、completed、failed 状态均允许改名，因为名称只是用户备注，不参与任务执行。

## 前端边界

- `frontend/lib/api/jobs.ts` 新增 `renameJob(jobId, name)`。
- `JobTable` 持有当前编辑任务 ID、草稿和行内错误；保存 mutation 成功后更新列表缓存或使 `queryKeys.jobs.all` 失效。
- 将当前 `JobAndProduct` 的整块链接拆为“详情链接内容 + 独立编辑按钮”，保持键盘可访问名称和图标的 `aria-label`。
- 不增加弹窗、详情页编辑入口、批量改名、自动生成名称、删除任务或新数据库字段。

## 并发与数据一致性

任务执行进度和改名可能同时更新同一行。仓储更新只写 `name` 和递增 `version`，不覆盖 `status`、`progress`、`result_payload` 或错误信息。保存成功后使用接口返回的名称更新列表；下一次轮询或查询刷新仍以数据库为准。

## 错误处理

- 404：显示“任务不存在或已被删除”。
- 422：显示“任务备注不能超过 100 个字符”。
- 网络或 5xx：显示“保存失败，请稍后重试”。
- 前端在提交前也限制 `maxLength=100`，但后端验证仍是最终约束。
- 错误信息只显示稳定中文说明，不暴露数据库或服务内部详情。

## 测试与验收

- Repository：改名成功、清空为 `null`、不存在返回空，并证明状态/结果不被覆盖。
- API：有效名称、首尾空格、空名称、超长 422、未知任务 404。
- API 客户端：PATCH 路径和请求体正确。
- 历史列表：点击编辑不跳转；初始值正确；Enter 保存；Esc 取消；清空恢复“未命名任务”；失败保留草稿并显示中文提示；只编辑当前行。
- 完成后运行相关聚焦测试、后端和前端全量测试、Ruff、TypeScript、生产构建；重启后确认 health ready 全部正常，历史页返回 200。

## 数据与兼容

不需要数据库迁移，既有 `analysis_jobs.name` 字段继续使用。旧任务名称立即可编辑；改名不会重新运行任务或模型，不消耗 Token，也不会改写历史分析结果。

## 回滚

回滚 PATCH 路由、schema、repository 方法、前端 API、行内编辑 UI 和对应测试即可；已保存的名称仍是合法的既有 `name` 数据，无需回滚或清理数据库。
