# 对比审判辅品身份展示与中文判断依据设计

## 目标

对比审判结果中的每个辅品应能直接识别，不再只显示英文标题和分数。折叠列表展示辅品首图、名称与商品 ID；展开详情继续展示完整身份信息。商品类型复核的判断依据优先使用中文，同时保留历史英文原文供核对。

本设计适配除食品外的全品类主品和辅品，不针对单一厨具商品编写特例。

## 范围与边界

- 新任务持久化每个辅品的标题、商品 ID、商品链接和首图。
- 旧任务只读取已经保存的数据，并可从原始辅品链接确定性提取商品 ID。
- 旧任务没有保存图片时显示“历史任务未保存图片”，不重新抓取、不伪造图片。
- 新任务的商品类型判断依据直接保存中文；需要时同时保留模型原始依据。
- 旧任务不重新调用模型。界面根据已有结论、来源、处理动作和证据生成稳定的中文概括，英文 `reason` 放入“查看英文原文”。
- 不修改评分、准入、食品过滤、供应商路由、模型调用次数或历史任务原始 payload。

## 数据结构

### 辅品元数据

在对比审判模型结果和顶层结果中新增可选的 `b_products` 数组，每项包含：

- `title`：辅品标题；
- `product_id`：从平台链接或采集结果取得的商品 ID；
- `product_url`：辅品原链接；
- `product_image`：采集图片数组中的第一张，没有则为 `null`。

序列化时使用实际参与分析的 `ProductDTO` 构建该数组。双模型结果各自可保存该字段，顶层活动结果按现有模型选择规则读取。

旧结果没有 `b_products` 时，前端从任务 `request_payload.b_urls` 与已解析的辅品顺序进行安全映射：仅在数量和顺序可唯一对应时补充 URL/ID；无法唯一对应时不猜测。图片只使用历史结果中真实存在的 URL。

### 商品类型判断依据

`ProductTypeReview` 新增可选字段：

- `reason_zh`：中文判断依据；
- `reason_original`：需要保留时存放原始依据。

新任务的复核提示词明确要求 `reason_zh` 使用简洁中文，说明“商品是什么、为什么属于食品或非食品、系统为何继续或阻断”。原有 `reason` 保持兼容，不删除。

## 前端展示

### 辅品折叠列表

每行从左至右显示：

1. 44–48 像素辅品缩略图；
2. 辅品名称；
3. `商品 ID：…`；
4. C 组合分、B 执行分；
5. 通过/否决状态、最终分和展开箭头。

无图时使用统一商品占位框，并显示“历史无图”或“暂无图片”，不使用主品图片代替。

### 辅品展开详情

抽屉顶部显示较大辅品图片、完整名称、商品 ID 和“打开商品”链接。其余否决审查、评分和证据内容保持不变。

### 中文判断依据

显示优先级：

1. `reason_zh`；
2. `reason` 本身包含中文；
3. 根据状态、判断来源、系统动作和证据字段生成中文概括；
4. 无可用信息时显示“历史任务未保存完整判断依据，请人工复核”。

如果原始 `reason` 为英文，则在中文概括下提供默认收起的“查看英文原文”。中文概括只陈述已保存事实，不逐句机器翻译、不增加商品事实。

## 兼容和错误处理

- 新字段全部可选，旧任务和旧 API 响应继续可渲染。
- 商品 ID 提取仅支持系统已经支持的平台 URL；提取失败显示“商品 ID 未记录”。
- 图片加载失败回退到占位框，不影响点击、评分或抽屉打开。
- 辅品元数据数量与解析结果不一致时，优先按规范化标题唯一匹配；仍不唯一则只显示已有名称，不跨商品借用图片或 ID。
- 历史英文原文保持原字符，不覆盖、不回写。

## 测试与验收

- 后端测试新任务序列化保存两个辅品各自的 ID、URL、标题和首图。
- 测试无图片、无 ID 和 Amazon/Walmart ID 提取边界。
- 前端测试折叠行与抽屉均显示正确辅品图片和 ID，且不会使用主品图片。
- 测试旧任务从 `b_urls` 确定性补充 ID，数量不一致时不错误匹配。
- 测试中文依据优先级、旧英文原文折叠和无依据回退。
- 运行前后端全量测试、TypeScript 检查、生产构建、健康检查和指定历史任务只读验收。

## 回滚

回退 `b_products` 序列化、前端元数据映射与展示、中文依据辅助函数和对应测试即可。无需数据库迁移，不删除任何历史任务数据。
