# V2.1 门禁与结果可解释性实施计划（已被全品类方案取代）

> 本计划已被 `docs/superpowers/plans/2026-07-31-all-category-non-ingestible-gates.md` 取代。后续不得按本文件实施，因为其中的分类测试范围不足以证明软件适配全品类非食品。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 消除“普通风险说明被当成硬拒绝”的误杀，使未知条件进入待补证据，并让结果页准确解释分数、准入状态和下一步动作。

**Architecture:** 模型只提供结构化三态门禁事实，服务器继续拥有最终裁决权。评分与准入分离：粘性分表达商业潜力，执行状态表达是否具备当前准入条件；前端只展示服务器持久化结论，不自行重算。

**Tech Stack:** Python 3.12、Pydantic、FastAPI、pytest、React 19、TypeScript、Vitest、Next.js 15。

## 最终验收标准

1. 普通风险说明不会产生硬拒绝。
2. 未知尺寸、材质、成分、承重和兼容性进入 hold。
3. reject 必须同时存在 blocked 状态、中文确认依据和来源事实。
4. 同批候选的异常同码模式会被质量门禁拦截。
5. V2.1 页面分数等于 API `stickiness_score`。
6. 页面不再重复显示“拒绝 / 不建议 / 淘汰”，而是显示一个主状态和下一步动作。
7. 历史任务不重算、不覆盖；真实新任务完成四端一致性验证。
